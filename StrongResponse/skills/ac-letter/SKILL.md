# AC letter

在逐题 Rebuttal 完成后，整理一份供 Area Chair 扫读的总结信。只做 AC letter，不负责逐题回复、审稿人画像或审稿模拟。

## 输入

- 完整 reviews、Overall 和 Confidence（若平台提供）。
- 当前完成的 Rebuttal 与关键证据位置。
- 二轮讨论原文、真实改分记录。
- 论文主要贡献、代码或材料的真实开放状态。
- 当轮 AC letter 的字数、匿名和链接规定。

## 写作顺序

1. 先感谢审稿人的时间与意见，再引用正面评价原话并报分。只有真实记录才写改分与认可；没有改分就省略。
2. 每位审稿人单独一个 3–4 句自然段：正面评价与评分 → 核心关切 → 作者已完成的回应 → 有证据的加粗结论。
3. 只概括最关键的数据、对照或修改，并给简短证据位置。不要复制整份 Rebuttal，不展开实验流程、方法细节或公式。
4. 如适用，简短说明真实的代码／数据开放状态，或明确仍属承诺的公开计划。
5. 结尾写：`We hope these clarifications support a fair and informed assessment.`

## 核对

- 引文忠于原意；每个分数、改分、认可、实验数字和修改都有真实来源。
- 没有二轮回应就不推测认可或问题解决，不能把作者结论冒充 reviewer 结论。
- 聚焦贡献与已经完成的回应；不制造全体共识，也不虚称全部问题解决。必要的剩余分歧如实交代。
- 不贬低或指挥审稿人和 AC，不请求接收，不要求按指定方式加权。
- 不用破折号连接句子。
- 全文不超过 500 个英文单词；当轮上限更低时遵守更低上限。

通用骨架见 [rules.md](references/rules.md)，复制提示词见 [prompts.md](references/prompts.md)。骨架依据原有规则整理，英文措辞仅供参考。输出可复制的英文信；词数、缺失材料与检查说明放在正文之外。只编辑作者授权的信件文件；提交另按作者授权执行。
