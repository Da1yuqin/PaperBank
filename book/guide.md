## 写在前头

StarPaper 提供可直接用于 Codex 的论文写作 skill（cs-paper-writing）和学术绘图 skill（starpaper-figures）。写作按章节加载，绘图覆盖 mainfig、framework、案例图、统计图和 LaTeX 图表。

本指南用于学术讨论，整理本人在论文写作与修改中的经验，供研究者参考。本人并非领域权威，内容可能有误。

网页开源并支持批注。欢迎指出错误、讨论具体写法，我会根据反馈修订。

*多数例子来自本人、本人参与或熟人的论文，另选少量具有参考价值的公开论文。各例均附出处；如用于研究，请引用对应原论文。*


先用 Codex 起草正文与关键图，再由作者审核逻辑、逐章精修。第四章为辅助工具。

主要面向方法与实证研究；按学科、研究类型和投稿要求调整。模拟段落明确标注，真实论文摘录另给出处与版本。

欢迎使用、改写、转载，也欢迎给 Codex 用作 skill。原创内容采用 CC BY 4.0，论文摘录与图片保留各自许可。转载原创内容请保留作者 Da1yuqin、[原文链接](https://da1yuqin.github.io/StarPaper/)和 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可，修改版本注明改动。如有帮助，欢迎 Star。

## 1. 初稿准备

准备研究材料与模板，确定正文结构，再进入[论文绘图](#figure-mainfig)。图先成型，方便合作者审阅；正文随后填充。

<a id="draft-step-1"></a>
### 1.1 研究材料与模板

先整理研究问题、已有局限、对应设计和真实结果，附上可核对的文献、图与数据。下载目标会议当年的官方模板，确认页数并编译。使用 Overleaf 时，将最新源文件同步到本地；Git 同步需要项目 owner 有会员或相应权限，没有则下载源文件 ZIP、本地编译，或跳过同步。写明允许修改的文件，再把材料填入提示词，让 Codex 先形成提纲和初稿。

**填写研究材料，生成初稿**

```text
读取 cs-paper-writing/SKILL.md：先读共享规则，只加载当前任务相关的章节 skill；不默认读全部例库。
核对目标会议及 track 的 AI 规定和材料使用权限，遵守当轮允许范围。未经许可，不向外部服务发送未公开稿件、review、个人数据或密钥。
会议、官方模板、正文页数与附录规定：【】
研究问题与已有不足：【】；真实设计与依据：【】
实验材料、指标口径、对照与真实结果：【】
结构适合的参考论文与想借鉴的部分：【】
允许修改的文件与范围：【】

1. 核对模板并编译，保留最新源、原始结果与合作者修改。
2. 先梳理参考部分的各节职责、论证顺序与输入输出衔接，再按自己的研究拟大纲。只借鉴组织，不复制措辞、事实或主张。
3. 完成关键图，确定问题、设计与证据的对应；绘图读取 cs-visuals，精修图形可另读公开绘图 skill。
4. 列章节标题、任务、证据与篇幅。Method Overview 接回具体困难并串起真实输入输出；模块开头先写动机，再写真实设计。
5. 按主张组织实验；整体结果、局部差异与独立条件分析分别给比较范围和分母。没有实际分析，不补标题或结果。
6. 引言先说明已有能力与具体不足，再逐项说明解法、机制用途和有依据的发现。段首承接具体对象，连接词服从真实逻辑。
7. 贡献用原生 itemize，固定三项：工作概述、新机制与实际用途、实验发现。第 2 项点名新设计及作用，不重复已经解释的障碍标签。
8. 先给我中文提纲和证据，再按当前授权写英文。检查真实数值、引用、图表、分页与最终 PDF；远端源和服务端 PDF 分开核验。
局限性按 cs-limitations：用一个自然段、First 和 Second 两点，让步说明有据工作与具体边界。

<a id="draft-step-3"></a>
### 1.2 正文结构

- 找一篇组织结构适合的参考论文，把想借鉴的部分交给 Codex。先让它梳理各节职责、论证顺序与章节衔接，再按自己的研究内容拟大纲；参考结构，不照搬主张或结果。
- 先列章节标题、各节要回答的问题、对应证据与篇幅。标题用具体对象或任务，不把多个无关动作塞在一节。
- 同一问题贯穿引言、相关工作、设计与实验。用 For [limitation], we [对应动作] 点名问题；结论回答原问题，局限全文一致。
- Method 的 Overview 先说设计为何处理局限，再概括后文各节的输入、输出与依赖；诊断型另交代瓶颈证据，基准型另交代系统输入与评分材料。
- 实验按主张安排：整体效果看主结果，设计作用用受控检验，能力边界看相关条件。诊断驱动研究还要复测原诊断。具体设置和写法见第 3 章实验部分。

#### 论文大纲与章节衔接

引言没有固定的模板数量。先按主要贡献选论证主线，再排全文章节；诊断驱动的论文要先把发现讲成立，不能只换一个引言标题。下列三套供借鉴，段落数、模块数和节号按实际内容调整。

| 论文类型 | 引言的论证顺序 | 正文的展开顺序 |
| --- | --- | --- |
| 方法论文 | 背景与回顾 → 局限 → 设计 → 发现 → 贡献总结 | Related Work → Method → Experiments → Conclusion |
| 基准与数据集论文 | 能力与评价 → 缺口及建设障碍 → 产物与设计 → 发现 → 贡献总结 | Related Work → Construction → Evaluation → Conclusion |
| 诊断驱动的改进研究 | 能力判断 → 质疑与发现 → 瓶颈 → 设计 → 验证 → 贡献总结 | Diagnostic Analysis → Method → Experiments → Related Work → Conclusion |

<details><summary>方法论文：大纲与章节衔接</summary>

核心贡献是一个新方法或系统设计。先说已知局限，再解释设计如何处理它，最后检验效果与设计作用。

<a id="draft-paper-outline"></a>
#### 方法论文：局限 → 设计 → 验证

填写方括号中的对象、动作与证据。节名和编号是示意；下图展示串行方法，实际并行或反馈应画出相应关系。

Abstract：压缩研究问题、主要贡献和关键发现；主张、术语与适用范围和引言、正文一致。通常在主要结果确定后定稿。

**1 Introduction**

为什么要研究[问题]？已有路线哪里不足？本文怎样处理？实验发现什么？

- **背景与比较**：先交代领域目标、已有进展与比较依据；前两段可以穿插或合并。

- **具体局限**：However, [limitation] ... 说明在什么条件下，现有路线为什么达不到[目标]。

- **核心工作与设计**：To address these obstacles, we introduce [name], a [亮点与用途]. 随后用 For [limitation], we [设计与作用] 逐项对应。

- **结果与贡献总结**：概述已验证的主要发现，再以 In summary, our contributions are: 和贡献列表收尾。

↓ 已有局限的比较依据在哪里？

**2 Related Work**

按共同任务或机制分组，说明真正相关的路线怎样工作。

- **每个主题收尾**：However, [与引言一致的具体缺口]. To address this gap, we [动作] [对象] based on [真实原则]. This enables [实际应用], addressing [同一缺口]. 三句依次写缺口、做法、应用与问题解决。

↓ 哪些设计处理这些局限，为什么这样设计？

**3 Method**

Overview：核心思想是[设计思路]。For [局限一], we [设计 A 的关键动作]，产生[中间产物 a]；[设计 B]用它处理[局限二]并产生[b]；[执行流程]将这些设计落实为[最终输出]。按实际节名和节号介绍对应作用。

↓ 概括各小节的职责与交接

3.1 Problem Formulation：定义任务输入、要求输出、目标与约束。训练、推理和评价各能看到哪些信息分开说明；已有定义较长时可另设 Preliminaries。

- **3.2 [设计 A 的具体名称]**：[任务输入 x] → For [局限一], [关键操作与依据]. → [中间产物 a]

- **3.3 [设计 B 的具体名称]**：[a] + [必要附加信息] → For [局限二], [关键操作与依据]. → [中间产物 b]

- **3.4 [训练、推理或评价流程]**：[b] + [执行所需材料] → 说明实际优化目标、运行步骤或评分协议；按论文类型选择。 → [最终输出 y]

串行示意：x → A → a → B → b → 执行流程 → y。箭头传递实际对象；并非每篇论文都需要两个模块或训练过程。

↓ 怎样检验整体目标与各项设计的作用？

Overview 说明后续小节怎样组成完整方法；模块数服从实际设计。训练和推理信息不同，应分别画清楚，不能把评分参考当作模型可见输入。

**4 Experiments**

按研究问题组织证据；先交代设置，再给主结果和针对性检验。

- **4.1 Experimental Setup**：数据版本与划分；Metrics 的定义、方向、分母和汇总；Baselines 的来源及可比条件；Implementation 的训练／推理、调参、预算与重复设置。说明误差条或区间的含义；人工或模型评分另交代协议与核验。

- **4.2 Main Results**：回答整体研究问题：实际结论 → 关键对照与图表 → 证据支持的含义及范围。

- **4.3 Design Validation（按需）**：围绕[设计为何处理局限]安排受控删除、替换或其他对照；说明变化因素、保留条件与耦合差异。基准论文可检验数据、判据或评分协议的有效性。

- **4.4 Further Analysis（按需）**：按主张选择泛化、敏感性、资源代价、错误分析或解释检验；每节回答一个具体问题。个例展示过程，频率结论仍需总体统计。

↓ 结果支持了什么，哪些解释和范围仍未得到验证？

**5 Discussion and Limitations**

解释发现与已有研究的关系，区分观察、可能解释和已验证机制；说明本文假设、覆盖范围、失败条件及影响。

- **按实际内容与投稿要求**：讨论可与分析合并；Limitations 可独立成节。数据授权、人类参与、隐私或风险等问题在适用时说明。

↓ 在实际证据范围内，开头的问题得到什么答案？

**6 Conclusion**

简短回答研究问题，概括已验证的贡献与发现；保留同一证据范围，不新增结果或设计。

References 支撑已有工作、定义与外部事实。Appendix 提供完整设置、算法或提示词、补充结果与复核材料；核心主张的必要证据不能全部藏在附录。局限、伦理与其他声明的位置按投稿要求确定。

[NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist) · 实验设置、可复核性、不确定性与结论范围可对照核查；上图的节名和顺序是写作模板。

<details><summary>基准与数据集论文：大纲与章节衔接</summary>

核心贡献是数据、基准或评价协议。先明确评价缺口，再讲产物如何构建、怎样评分，最后分析被评价系统的表现。

<a id="draft-benchmark-outline"></a>
#### 基准与数据集论文：评价缺口 → 构建 → 测评

核心产物是数据、基准或评价协议。先定义并构建评价对象，再报告系统表现及诊断；不要求虚构一个新模型。

Abstract：压缩研究问题、主要贡献和关键发现；主张、术语与适用范围和引言、正文一致。通常在主要结果确定后定稿。

**1 Introduction**

为什么现有评价还不能回答[能力问题]？本文提供什么输入、判据或协议？

- **背景与已有评价**：回顾能力和评价方式，比较同一目标、输入与判据；不把“未报告”写成“没有”。

- **评价缺口与建设障碍**：先讲无法区分的[行为]，再讲收集[数据]或构建[判据]为什么困难；两类问题分别接到设计。

- **产物与对应贡献**：To address these obstacles, we introduce [name], a [亮点与评价用途]. For [评价局限], we [数据或判据设计].

- **测评发现与贡献总结**：先概述真正有信息量的发现，再总结数据、评价设计及发现的独立贡献。

↓ 哪些相关路线支持这个比较？

**2 Related Work**

按任务或评价目标归类，说明已有输入、判据和覆盖范围。

- **每个主题末尾**：However, [与引言一致的具体缺口]. To address this gap, we [动作] [对象] based on [真实原则]. This enables [实际应用], addressing [同一缺口]. 三句依次写缺口、做法、应用与问题解决。

↓ 对应的缺口怎样落实为评价设计？

**3 Benchmark Construction**

Overview：评价[目标能力]需要[输入与判据]。我们将[来源材料]构造成[案例]，再据此定义[评价准则]；受测系统生成[回复]，评分者按[证据与准则]评估它。下面分别讲案例、判据与评分协议；若还提出辅助方法，另讲其作用。

↓ 概括各小节的职责与交接

3.1 Problem Formulation：定义任务、系统输入 x、回复 y、参考证据 r 与评分目标。系统可见材料和评分者可见材料分开。

- **3.2 Data / Case Construction**：[原始来源材料] → 说明来源范围、筛选或采样、标注与数据划分，产物对应前文的评价缺口。 → [案例 x 与参考证据 r]

- **3.3 Evaluation Criteria**：[案例 x、参考证据 r] → 定义判据及制定依据；说明如何区分目标行为、可接受答案与错误。 → [准则 c]

- **3.4 Response Assessment**：[回复 y] + [x, r, c] → 说明评分者、评分步骤、汇总和必要核验；此处定义协议，下一章执行测评。 → [评分与报告格式]

资料流：来源 → 案例 → 准则 → 评分协议。另一路：受测系统接收 x，生成 y；评分者结合 y、r 和 c 评分。不能让评测参考泄漏到系统输入。

↓ 用这套评价实际看到了什么，它是否测到了目标能力？

有独立的辅助方法时，在构建章内或单独设节，解释它与评价目标的关系；没有就不加。判据制定、评分执行与结果分析分清职责。

**4 Evaluation**

交代可比设置，概述主要发现，再解释差异、失败及评价边界。

- **4.1 Evaluation Setup**：交代数据划分、受测系统、运行条件、指标、评分协议和不确定性；评分核验放在读者理解评分的位置。

- **4.2 Main Results**：To answer [研究问题], we evaluate [系统]. 先给发现，再给关键比较和支持范围；不从一串模型名或分数排名开讲。

- **4.3 Evaluation Validation（按需）**：围绕“确实测到[目标]”安排有区分力的对照、判据或评分核验；不能只用一次总分比较证明评价有效。

- **4.4 Scenario / Error Analysis**：按条件或失败模式回答具体问题；个例解释过程，频率或普遍性结论要有总体统计。

↓ 哪些结论得到支持，哪些条件仍未覆盖？

**5 Conclusion**

回答最初的评价问题，概括产物和主要发现；不把覆盖范围写成真实使用频率。

**Limitations / Ethics Statement**

说明来源与任务覆盖、判据及评分边界，按实际研究说明授权、隐私或风险。

References 支撑已有工作、定义与外部事实。Appendix 提供完整设置、算法或提示词、补充结果与复核材料；核心主张的必要证据不能全部藏在附录。局限、伦理与其他声明的位置按投稿要求确定。

</details>

<a id="structure-diagnostic"></a>
<details><summary>诊断驱动的改进研究：大纲与章节衔接</summary>

先通过实验揭示问题、定位瓶颈，再据此提出并验证改进。诊断是独立贡献，方法和验证都要回扣它。

<a id="draft-diagnostic-outline"></a>
#### 诊断驱动的改进研究：发现问题 → 定位瓶颈 → 改进验证

诊断在方法之前成立。诊断条件和观察维度会在后续验证中再次出现；只做主结果表，回答不了最初发现的问题。

Abstract：压缩研究问题、主要贡献和关键发现；主张、术语与适用范围和引言、正文一致。通常在主要结果确定后定稿。

**1 Introduction**

已有成绩是否真的代表[目标能力]？诊断发现什么，瓶颈在哪里，本文怎样回应？

- **背景与能力判断**：介绍已有路线及成绩，说明这些成绩通常被理解成什么能力。

- **质疑与诊断发现**：However, [能力质疑]. 说明[受控诊断]如何检验它，紧接最有信息量的观察。

- **瓶颈与设计判断**：进一步对照区分可能解释；说明有证据支持的[瓶颈]为何需要[设计思路]。

- **方法、验证与贡献总结**：概述针对瓶颈的设计及主要验证，最后总结诊断发现、方法与验证贡献。

↓ 先把质疑变成可检验要求，再给诊断证据。

**2 Diagnostic Analysis**

在介绍改进方法前，先证明问题存在，并给出定位瓶颈的依据。

- **2.1 Testable Hypothesis**：把[目标能力]转成在[受控条件]下应该满足的可检验要求。

- **2.2 Diagnostic Data and Protocol**：说明改变了哪个条件、保留了什么，如何控制相关混淆因素及比较预算。

- **2.3 Findings and Diagnostic Controls**：报告目标表现与过程症状，使用有区分力的对照检验解释；不能把相关变化直接当作因果机制。

↓ 诊断指出的瓶颈，成为方法每项设计的理由。

**3 Proposed Method**

Overview：诊断表明[瓶颈 A]妨碍[目标]。For [瓶颈 A], we [设计 A]，产生[a]；[设计 B]用它处理[瓶颈 B]，产生[b]；[训练或执行流程]把它们落实为[y]。先讲为什么这样设计，再展开输入输出与依赖。

↓ 概括各小节的职责与交接

3.1 Overview / Problem Formulation：定义必要对象及训练、推理输入输出；已在诊断章定义的对象直接承接，不重写一遍。

- **3.2 [Design A]**：[任务输入 x] → For [诊断瓶颈 A], [设计动作与依据]. → [产物 a]

- **3.3 [Design B]**：[a] + [必要信息] → For [诊断瓶颈 B], [设计动作与依据]. → [产物 b]

- **3.4 [Training / Execution]**：[b] + [执行材料] → 给出实际训练目标或执行流程；按方法选择，不强加训练步骤。 → [最终输出 y]

每项设计都接到诊断中的具体瓶颈；箭头交接真实对象，模块数量与关系按实际方法调整。

↓ 既要验证主任务表现，也要复测原诊断，看最初的失败是否缓解。

诊断章的假设、对照与发现要能独立读懂；方法的引出不能替代对问题本身的验证。

**4 Experiments**

围绕诊断和设计安排验证；终点表现、诊断复测、过程证据各回答不同问题。

- **4.1 Experimental Setup**：说明数据、基线、指标与公平比较条件；诊断章已有协议只补新增条件。

- **4.2 Main Results**：回答改进方法在主要任务上是否有效，说明例外与范围。

- **4.3 Diagnostic Robustness**：复用第 2 章的诊断条件，检验原有失败是否缓解及其范围。

- **4.4 Process / Mechanism Analysis**：复用诊断维度，看过程变化是否符合瓶颈解释；机制主张需要有区分力的检验。

- **4.5 Ablation / Alternative Explanations**：检验关键设计，按当前主张控制额外预算、提示或其他替代解释。

↓ 比较这些证据是否共同支持原来的设计判断。

**5 Related Work**

围绕已明确的问题和设计比较相关路线；主题末尾用 However 说明局限，紧接本文处理方式。

- **位置选择**：可像此模板放在实验后，也可放在引言后；前置时让读者先获得必要概念，后置时突出诊断主线。

↓ 回到最初的能力问题，收束诊断与验证。

**6 Conclusion**

回答[目标能力问题]：诊断揭示什么，设计怎样回应，证据支持到什么范围。

**Limitations / Ethics Statement**

局限与引言、诊断和结论一致；说明仍未解决的问题及适用范围。

References 支撑已有工作、定义与外部事实。Appendix 提供完整设置、算法或提示词、补充结果与复核材料；核心主张的必要证据不能全部藏在附录。局限、伦理与其他声明的位置按投稿要求确定。

</details>

只有实证发现、没有改进方法时：Introduction → Study Design → Results → Robustness / Further Analysis → Discussion → Conclusion。引言按“问题 → 证据缺口 → 研究设计 → 发现 → 贡献总结”组织；删去改进方法及其消融。Related Work、局限及声明的位置按论证和投稿要求调整。

#### 引言的贡献总结：默认保留的格式

先用连贯段落讲清核心工作、设计为何对应局限，以及实验发现。方法名后的同位语立即交代亮点与用途；不要让读者读完一串流程才知道贡献。

【铁律】普通正文引导句后接原生 itemize；固定三项，列表后直接下一节，不追加目录预告、链接或新结果。

【铁律】普通正文引导句后接原生 itemize，固定三项：工作概述、新机制与实际用途、实验发现。第 2 项用 We propose [机制] 点名真正的新设计，说明依据、具体作用及实际应用；正文已建立问题与解法时，不再重复障碍标签。第 3 项给证据范围，新名称首次就近定义，列表后直接下一节。

三项是本套 CS 写作约定，不是所有会议的官方要求。论文类型与当轮要求优先；先删重复背景和次要流程，不用改模板规避篇幅限制。

3. 按最终宽度起稿。所有标题、坐标、刻度、图例、数字、注释用同一字号，正文减 2 pt ≤ 图字 ≤ 正文，字体家族匹配。放不下就重排或拆图，不缩小规定字号、不进行非等比缩放、不修改论文模板。
4. 白底、近白面板、深色文字、低饱和配色。同一对象全篇同色，用形状或线型辅助区分；不加渐变、阴影和装饰光效。通栏先参考 16:9，单栏参考 4:3，内容与可读性优先。
5. 模块名与正文一致。缩写、变量、单位、图标、颜色和线型都能解释；图标旁写对象名。标签用自然语言，不用符号拼句。
6. 同一案例全文只呈现一次，翻译、裁剪或改名仍算同一个。先按来源核对使用位置，其他位置交叉引用。对话一轮一框；作者示例与实测回复分清，没有评分不画勾。
7. 统计图用 Python 等专业工具读取所附数据，保留数值、坐标几何、分母、单位与 SD／SE／CI 定义；同类比较统一尺度。不为美观补缺测、改数据或平滑曲线，不重跑实验；KDE 等估计图说明样本量、方法和带宽。概念图按当前环境使用 imagegen，生成内容须依据已确认流程，不生成虚构结果。
8. Caption 先说明图是什么，再解释必要标记和术语，按实际面板或上下左右读序带读，最后给有证据的发现与贡献意义；简称在本条 Caption 写全称。方法图说明机制，不编实验结论。尽量三行，必要定义与事实边界优先。
9. PDF 文字可见、可选，字体嵌入；不叠两套字形或隐藏 OCR。统计图优先矢量 PDF，含位图的 PDF 不称全矢量。CS 图表默认 [!t]，实际位置跟随正文首次引用，保留附录归属。
10. 先给问题、布局和缺口，再绘制。插回论文编译，看最终页面的字号、图例、裁切、碰撞和引用顺序。交付源文件、PDF、预览及实际检查结果。只改色时保留原布局、文字、连线与图片；保留他人修改，不扩大范围。
每图自身解释简称，案例条件对应难点，颜色点明对象。Caption 保留全图读法，单项判定用 \footnote 与 \footref；跨栏脚注可用 savenotes，并查落页与跳转。评分通过不写成真实执行。移图到附录同步详解、Overview 和引用；显示改名不改冻结记录。
```

### 2.2 Framework

<a id="general-rules"></a>
### 3.1 全文规范

“铁律”只标必须遵守或禁止违反的要求；未标记的是可调整的写法建议。官方规定优先，特定稿件的要求不套用到其他论文。篇幅利用和实验页呈现来自作者笔记，不是会议的最低页数规定。

#### 篇幅与版面：充分呈现证据

- **【铁律】遵守当轮篇幅要求：**按会议上限和当前稿件明确的篇幅目标排版。要求写满时，补足有效证据、比较和解释；明显偏短可能让审稿人觉得实验和分析不足。不为凑页注水，不把单稿页数套到所有论文。

- **【铁律】实验页有可见证据：**正文末几页用于实验时，每页应有实际结果、分析图或对照表，与解释就近排。核心证据别全移附录，也不为凑页拆成零碎实验。

- **【铁律】保留支撑结论的证据：**不能为省篇幅删掉支撑结论的实验分析、必要条件和关键比较。超页建议先删重复和无关背景，再压缩 Related Work 与常规方法介绍。

- **【铁律】保持官方模板：**按当轮规则分别核查正文、参考文献与附录的页数，不改字号、行距、字距或页边距凑页。最终看 PDF，源码长度不能代替版面检查。

- **【铁律】图表与正文一致：**同一对象的名称、符号、单位、数值和范围对齐；图表就近引用，caption 解释读法。改图或改表后回查正文，避免留下两个版本。

#### 逻辑：句子承接与对象一致

- **先说为什么值得做：**每项设计都要回答：已有做法在哪种条件下不足，本文改了什么，为什么有用，哪项证据支持。

- **【铁律】句子之间有逻辑关系：**后句处理前句的问题或产物，Then 和 Therefore 须符合实际关系。

- **【铁律】连接词用对：**转折用 However，有推导依据才用 Therefore；展开已有判断用 Specifically，并列直接写。连接词由真实关系决定。

- **【铁律】不虚构章节依赖：**章首说明承接的问题或产物；确有后续用途时，章末说明产物交给谁。不把并行写成串行。Related Work 小节直接进入内容，Intro 以贡献列表结束，Conclusion 不预告不存在的下一步。

- **【铁律】问题、设计、实验对应：**引言提出的问题，方法处理，实验检验。

- **【铁律】钩子连接真实关系：**前句建立对象或前提，后句增加判断。Therefore 从证据归纳，Specifically 展开判断，However 说明具体转折；举例用 For example 或 For instance 起句。缺少某项设计后，紧接说明因此无法区分什么；连接词不能代替依据。

#### 语言：完整判断与句长

- **用具体操作替代空泛评价：**用具体操作替换 powerful、comprehensive 等空评价。

- **【铁律】短句，完整动作：**每句一个主要判断，不用分号把长句接回来。按最终 PDF 检查：常用双栏窄栏句子最多 3 行，单栏约 1.5 行；本稿另有明确要求时按本稿执行。保留动作、条件与承接，不缩字体或改模板。

- **【铁律】正文写完整句子：**正文用完整句子表达关系，不用加号、斜杠、与号或箭头代替文字；英文不用破折号插入解释，复合词连字符、数学、单位和图连线保留。

- **同级小节篇幅相称：**任务相近，篇幅尽量接近；太长先查重复，复杂内容分段。

- **【铁律】近距离用词去重：**检查同句、相邻句和短段中的实义词、词根与起句重复。删冗余，不靠换同义词掩盖重复，也不删必要术语。

#### 术语：首次定义与名称一致

- **【铁律】术语首次解释：**写清对象和用途，不让读者到后文找定义。

- **【铁律】符号首次定义：**写对象、来源、算法、用途和下标；不用的符号删掉。

- **【铁律】同一对象同一称呼：**同一对象同一名称；代词的对象须唯一、明确且就近。含混时换成短对象名，清楚的代词保留。

- **【铁律】贡献词有事实依据：**tailored、expert-confirmed、manually selected 等修饰须对应可核查工作。贡献对象与动作前置，修饰词不能代替贡献。

- **命名发现立即解释：**发现需要命名时，选准确、好懂的短名，通常不超过四个英文词。定义和证据仍须给出，名称不能代替解释。

#### 主张：证据与适用范围

- **【铁律】保留结论条件：**任务、模型、范围和分母写清；有限测试不推广所有场景。

- **【铁律】观察与原因分开：**先报告现象，再讲可能原因；匹配对照支持后才归因。

- **结果首句写发现：**结果段首句给有依据的发现，随后给图表、关键比较和意义；先读完一段设置才找到结论，会增加阅读负担。

- **【铁律】数字与统计口径准确：**数字用阿拉伯数字，并能回查最新记录。子集给 n of N、单位与版本；区分百分比与百分点、宏平均与微平均。未知不填 0，不能换分母或单位夸大结果。

### 3.3 摘要

让人用一段话看懂为什么这项工作值得做。

#### 本节原则

- 【铁律】摘要一个自然段，按背景、具体 limitation、对应方法与亮点、实验亮点组织。不用设问或术语定义代替不足；缺一环，就看不出研究为何必要、做了什么或证据是什么。长度服从会议要求。
- 【铁律】贡献对象和动作尽早出现。关键改动要回应前句的不足，不先堆流程和数量。
- 【铁律】必要术语首次解释，缩写给全称；句间的对象与逻辑关系明确，不能让读者猜。
- 结果优先保留有信息增量的发现及比较范围，不机械以最大数字结尾。摘要通常不放引文，按会议要求处理。
- 【铁律】摘要解法逐点写 For [具体 limitation], we [实际动作与贡献].，点名前文同一限制。
- 【铁律】改动摘要或引言后，回读另一节；问题、设计、命名、数字、模型范围和因果方向持续对应，不逐字照抄。

<a id="annotated-abstract"></a>

#### 摘要结构

假设教学段落，非论文原文或实测结果。

**English 教学改写**

Document-based dialogue requires answers that respect both source evidence and evolving user constraints. Passage-only generation supplies relevant text without explicitly recording which dialogue constraints the source quotes support. For this missing evidence-to-constraint link, we introduce structured evidence notes that pair source quotes with manual locations and active dialogue constraints. These notes let the generator cite sources and explain how the evidence relates to each constraint. In our comparison on static English manuals, notes increase citation support relative to direct generation but add latency. The comparison evaluates source support; the support scores do not establish that every user constraint is satisfied.


**中文译文**

基于文档的对话要求答案同时符合来源证据与不断变化的用户约束。只使用片段的生成方式提供相关文本，却不明确记录来源摘句支持哪些对话约束。针对证据与约束之间缺少对应记录的问题，我们提出结构化证据笔记，将来源摘句与手册位置及当前有效的对话约束配对。这些笔记帮助生成器引用来源，并说明证据与各项约束的关系。在针对静态英语手册的比较中，相比直接生成，笔记提高了引用支持率，但增加了延迟。这个比较评价的是来源支持，不能据此认定每项用户约束都得到满足。


**高亮与旁批**

1. **both source evidence and evolving user constraints / 来源证据与不断变化的用户约束**：任务需求写具体。证据与用户约束是两类要求。先建立它们，下一句的不足与后面的设计才有对象。
2. **without explicitly recording which dialogue constraints the source quotes support / 却不明确记录来源摘句支持哪些对话约束**：【铁律】把缺口缩到本文负责的部分。承认片段提供了相关文本，再限定缺口：没有显式记录证据与约束的对应。对应设计也必须处理这个缺口。
3. **For this missing evidence-to-constraint link, we introduce structured evidence notes that pair source quotes with manual locations and active dialogue constraints. / 针对证据与约束之间缺少对应记录的问题，我们提出结构化证据笔记，将来源摘句与手册位置及当前有效的对话约束配对。**：【铁律】For 点名缺口，紧跟产物与动作。For 接回上一句缺少的证据与约束对应记录；we introduce 立即报新产物，再用 pair 说明摘句、位置和约束怎样配对。
4. **notes increase citation support relative to direct generation but add latency / 相比直接生成，笔记提高了引用支持率，但增加了延迟**：发现与取舍一起交代。这个假设案例保留引用支持率和延迟的取舍。真实论文换成核验过的结果，不逐项罗列排名。
5. **the support scores do not establish that every user constraint is satisfied / 不能据此认定每项用户约束都得到满足**：【铁律】别让指标越界。引用支持率测来源支持，不能代替约束满足率。实际摘要只保留会影响结论理解的边界。

### 3.4 引言

让读者认同问题，并记住你的解法为什么有用。

#### 本节原则

- 【铁律】钩子承接前文真实问题、困难或产物，不能错置转折、目的与因果。However 可写转折，Therefore 据前述证据归纳，Specifically 展开判断；不是每段都要出现这些词。
- 【铁律】前两段可穿插、合并或拆分，但要有领域回顾与已有方法比较。回顾给局限铺路：后面批评什么，前面先说明已有方法怎样处理它。
- 【铁律】挑战名称本身就要显示困难：什么缺失、什么难以完成、什么阻碍目标。随后解释原因和影响，中性任务属性不能直接当挑战名。
- 【铁律】贡献对象与动作尽早出现。expert-confirmed、manually selected、tailored 等词要对应实际工作；写清选择依据，不用“高质量”代替依据。
- 【铁律】方法段首承接已建立的障碍；方法名后同一句说明产物、核心设计与用途。随后逐项点名困难及对应解法，服从当前人工定版，不把 Therefore 或 To solve 设为永久必需。引言讲设计思路，实现细节留给 Method。
- 结果段可先接回研究问题，再概述发现；摘要压缩、引言展开，不逐字重复，不把排名当分析。
- 【铁律】摘要、引言及正文的问题、设计、名称、数字、范围与因果方向一致；每次修改后回读对应部分。局限沿用同一名称，Related Work 给比较依据，Method 说明设计，实验提供检验。
- 【铁律】结果概述对应正文实际结论。若实验只支持某些任务或条件，摘要、引言、讨论和结论都限定到相同范围。
- 【铁律】引言只引用属于本节的图表；不提前指向后文方法、实验、附录的图表、公式或章节，也不写“见后文”。文献 citation 与有依据的结论保留。
- 【铁律】引言中的正式命名对象每次出现用斜体，强调性加粗对同一对象全节最多一次；贡献列表不重置次数，普通专业词不机械斜体。
- 【铁律】普通正文引导句后接原生 itemize，固定三项：工作概述、新机制与实际用途、实验发现。第 2 项用 We propose [机制] 点名真正的新设计，说明依据、具体作用及实际应用；正文已建立问题与解法时，不再重复障碍标签。第 3 项给证据范围，新名称首次就近定义，列表后直接下一节。

<a id="intro-body-map"></a>
#### 引言如何贯穿全文

引言列出全文要回答的问题。相关工作给依据，方法给设计，实验给检验，讨论与结论收束解释和范围。

这是可填空的功能对应图，不规定句数、段数或局限数量。方括号填同一组对象；同色高亮与箭头表示哪些内容必须相互对应。

- **Q · 研究问题：**全文回答同一个具体问题。

- **L → M → E · 局限、设计与检验：**前人的哪项不足，由哪项设计处理，用什么证据检验。

- **D · 实施困难：**完成本文研究时遇到的困难；有必要才单独展开。

- **B · 本文剩余局限：**限定本文已经解决到哪里，和前人局限 L 分开。

**A · 背景与已有研究**

[已有研究]已经说明[已知能力或发现]，这些结果支持[应用目标或进一步研究]。

句首钩子：`These findings motivate [the research question].`

- [相关工作](#chapter-related) · 核实已有起点：说明[已有路线]的实际能力、输入和适用条件，并给原论文依据。
- [方法](#chapter-method) · 区分已有与新增：说明哪些能力来自已有方法，本文新增了什么设计。

背景不占用本文贡献；前人已经提供的能力须承认并引用。

**Q · 研究问题**

[研究背景或实践需求]提出[具体研究问题 Q]。

句首钩子：`To answer [the specific research question], we ...`

- [方法 · 任务定义](#chapter-method) · 定义对象与目标：将 Q 对应到[研究对象]、[任务定义或变量关系]和[可观测量]；系统任务再写输入、输出与约束。
- [实验 · 研究问题](#chapter-experiments) · 给出检验方式：用[数据与比较条件]和[对应指标]检验 Q。
- [结论](#chapter-conclusion) · 回答开头：依据实际结果，在[已研究条件]内回答 Q。

任务、指标与结论测的是同一对象和能力；代理指标的改善不能直接写成未测过的真实应用收益。

**L1 → M1 → E1 · 已有局限与对应解法**

However, [已有路线]在[具体范围]存在[局限 L1]，因而妨碍[目标 Q]。For [局限 L1], we [设计 M1 的具体动作].

句首钩子：`For [limitation L1], we [specific design action].`

- [相关工作 · 主题收尾](#chapter-related) · 给 L1 比较依据：However, [L1]. To address this gap, we [M1 的实际动作] [对象] based on [真实原则]. This enables [实际应用], addressing [前述同一缺口].
- [方法 · M1](#chapter-method) · 解释为什么这样设计：[M1]针对 L1 的哪项原因采取什么操作，产生什么结果供后续使用。
- [实验 · E1](#chapter-experiments) · 检验原动机：用[能检验 M1 作用的对照 E1]检查[与 L1 对应的指标或行为]。

三处沿用同一个局限名称和比较范围。“未报告”不写成“没有”；只有整套系统对比时，不能宣称单个设计造成了收益。

**L2 → M2 → E2 · 另一项独立局限（按需）**

此外，[独立局限 L2]影响[另一必要能力]。For [独立局限 L2], we [设计 M2 的具体动作].

句首钩子：`For [limitation L2], we [specific design action].`

- [相关工作 · 另一主题](#chapter-related) · 说明 L2 有何不同：给 L2 的比较依据，紧接 M2；不要换词重复 L1。
- [方法 · M2](#chapter-method) · 交代独立作用：说明 M2 使用什么输入，怎样满足[与 L2 对应的要求]。
- [实验 · E2](#chapter-experiments) · 给对应检验：E2 检验[与 L2 对应的能力]，结果段沿用同一问题并解释实际发现。

有独立不足才增加这条链；不为凑“两项局限”重复同一问题。

**D · 实施困难（按需）**

完成[研究任务]还受到[实施困难 D]约束；这会阻碍[必要步骤]。

句首钩子：`Establishing [the required artifact] requires [specific step].`

- [方法 · 构建或研究设计](#chapter-method) · 给可执行解法：说明实际来源、选择规则、操作与产物怎样处理 D。
- [附录](#chapter-appendix) · 补可复核材料：提供[与 D 的解法对应的协议、配置或材料]，并从正文定位。

D 是本研究怎样完成的困难，不等于前人局限 L；来源或权限问题须按实际交代，不能省略会影响判断的信息。

**M · 核心设计与贡献**

To address these obstacles, we introduce [name], a [核心亮点与用途]。For [同名局限], we [核心设计的具体动作].

句首钩子：`For [named limitation], we [concrete contribution].`

- [方法 · Overview](#chapter-method) · 展开贡献与依赖：先解释核心思想和每项设计的作用，再概括各节的输入、操作与输出。
- [框架图与图注](#figure-framework) · 显示同一操作关系：图中对象、名称和方向与正文一致；按实际画串行、并行或反馈。
- [实验 · 设置与设计检验](#chapter-experiments) · 固定能判断作用的条件：比较条件与[要检验的设计作用]对应；说明固定项及无法完全对齐的差异。

引言交代亮点与用途，方法给实现依据，实验给检验；产物介绍、流程说明和效果证据各有职责。

**E → Q · 主要发现**

To answer [Q], we evaluate [研究对象] under [条件]。实验发现[主要结论 E]，回答了[Q 的哪一部分]。

句首钩子：`To examine [the motivated capability], we compare [objects].`

- [实验 · 主结果与分析](#chapter-experiments) · 先结论，再证据：报告 E 对应的关键比较、图表、指标口径和不确定性。
- [实验 · 回扣动机](#chapter-experiments) · 解释回答了什么：说明 E 是否支持[原设计目标]；改善、无支持或失败都对应同一个问题。
- [摘要与引言](#chapter-abstract) · 压缩同一发现：摘要压缩 E，引言概述 E；名称、数值、对象和范围与实验一致。
- [讨论](#chapter-discussion) · 限定解释：区分观察到的差异、可能原因与已验证机制。

实验结论必须回到最初动机；缺少受控检验时不补因果解释，案例展示也不能代替总体频率。

**C / B · 贡献与结论范围**

本文提供[新增贡献 C]并揭示[实际发现]；结论限于[已验证范围]，仍受[本文剩余局限 B]约束。

句首钩子：`Within [the evaluated conditions], [supported conclusion].`

- [讨论与局限](#chapter-discussion) · 解释 B 的影响：说明[未覆盖条件或假设 B]怎样限制结论；未测试不等于已失败。
- [结论](#chapter-conclusion) · 闭合 Q：回答 Q，概括已验证的贡献与发现，保留同一范围。
- [摘要与引言](#chapter-abstract) · 反向校准主张：若证据只支持[有限范围]，摘要、引言和贡献句都缩至该范围。

L 是前人的不足，B 是本文解决到哪里。真正限制核心主张的 B 须体现在相应主张中，不要求把所有局限都塞进引言。

L1 → M1 → E1 → Q：[具体局限] → [针对它的设计] → [能检验设计作用的比较] → [对研究问题的实际回答]。

其他主张：数据质量、效率、泛化或机制主张同样需要对应证据；按实际贡献增加，不能只靠同一句钩子。

**结果回写**：实际发现及范围 → 摘要、引言的贡献与发现 → 讨论与结论。结果或证据范围变了，对应主张一起改。

- 【铁律】使用原生 section / subsection；主题标题独占一行，在最终 PDF 最多一行，不以 paragraph 或行内粗体代替。

#### 方法比较

**English 原文**

Multi-dancer generation is an emerging area currently in its nascent stage. To the best of our knowledge, only a handful of studies (Yao et al. 2023; Le et al. 2023b,a; Yang et al. 2024) have focused on generating scenarios for more than two dancers. Among these, GDanceR (Le et al. 2023b) and GCD (Le et al. 2023a) utilize no special structures to avoid the imbalance issue in motion representation, resulting in a tendency for dancer ambiguity. CoDancers (Yang et al. 2024) splits group motions into single-person motions, preventing the occurrence of dancer ambiguity. However, completely isolating individual features results in incomplete group information, which leads to disharmony generation results. Therefore, a more optimal feature separation strategy is necessary. In this work, we introduce TCDiff, a method that first generates dancers’ trajectories and then produces logical movements. Together with our proposed effective plugin, Fusion Projection, this approach significantly reduces dancer ambiguity.


**中文译文**

多舞者生成是一个仍处于早期的新兴方向。据我们所知，只有少量研究（Yao et al. 2023; Le et al. 2023b,a; Yang et al. 2024）关注超过两名舞者的场景。其中，GDanceR（Le et al. 2023b）和 GCD（Le et al. 2023a）没有采用专门结构来避免运动表示的不平衡，因而容易出现舞者混淆。CoDancers（Yang et al. 2024）将群体动作拆成单人动作，避免了舞者混淆。然而，完全隔离个体特征会造成群体信息不完整，进而导致生成结果不协调。因此，需要更合适的特征分离策略。本文提出 TCDiff，先生成舞者轨迹，再生成合乎逻辑的动作。该做法结合我们提出的有效插件 Fusion Projection，显著减少了舞者混淆。


**高亮与旁批**

1. **utilize no special structures to avoid the imbalance issue in motion representation, resulting in a tendency for dancer ambiguity / 没有采用专门结构来避免运动表示的不平衡，因而容易出现舞者混淆**：先统一比较维度。两项工作按表示机制归类，有共同尺度。“表示不平衡→舞者混淆”仍需定义或文献依据。
2. **splits group motions into single-person motions / 将群体动作拆成单人动作**：承认别人解决了什么。先承认拆成单人动作处理了舞者混淆，再谈代价。后文才说得清本文要同时保留什么。
3. **completely isolating individual features results in incomplete group information / 完全隔离个体特征会造成群体信息不完整**：代价接上了，对象还可更具体。不足来自前一句的完全隔离，逻辑接得上。但“群体信息”仍宽泛；写自己的论文时应指出缺哪种关系。
4. **a more optimal feature separation strategy is necessary / 需要更合适的特征分离策略**：“更合适”还不够。收尾应说清需要兼顾个体区分与群体协调。“更合适的策略”本身不能代替设计目标。
5. **first generates dancers’ trajectories and then produces logical movements / 先生成舞者轨迹，再生成合乎逻辑的动作**：操作还要解释作用。先轨迹、后动作给出顺序，还需说明怎样回应前面的两种代价。Fusion Projection 也要讲机制，不能只写 effective。

### 3.7 实验

用对照检验贡献，解释主要差异与发现。

#### 本节原则

- 先把 Intro 的核心主张变成可检验的问题，再安排主结果、消融和必要的扩展实验。RQ 是组织工具，不必每表编号。
- 诊断分析可按证据层级推进：先讲整体发现，再用 However 点明整体结果掩盖的局部差异，最后用 Separately 或 Next 引出独立条件分析。各层只回答自己实际检验的问题，不给没有这类分析的论文硬套标题。
- 【铁律】指标交代真实定义、方向、单位、分母、汇总及无效输出处理；基线说明真实路线与版本，比较口径不能混用。
- 【铁律】写清会改变结果的条件：数据版本与划分、参数值、训练或推理预算、评价方式，以及可获知的相关硬件条件。正文、附录及发布配置对应同一执行版；改了 prompt 或判据，不能把旧分数算成新版结果。
- 设置可按 Metrics、Baselines、Implementation Details 排列。结果段建议先加粗一句具体发现，再给关键对照与意义，接回 Intro 的问题，不逐行读表。
- 【铁律】判断单个因素的独立作用时，固定其他条件；多因素共同变化，只能评价整套改动，不能把收益归给其中一项。
- 【铁律】声称效率或稳定性时，给出相应测量与口径。效率计入所声称系统的完整成本，稳定性对应真实重复变化；重要代价和负结果不能省略。
- 实验章首承接方法或数据构建，概述真实被测对象与主发现，再用 Specifically 或自然钩子展开具体分析。名单、设置与分析拆成完整短句。
- 【铁律】主张必须有对应证据。整套方法的结果不能证明未经检验的模块各自有效，不强制每项设计都单独做一次消融。
- 【铁律】报告实际重复次数和重复单位，说明均值旁是 SD、SE 还是 CI。模型、案例与随机种子不能混作同一统计单位；排名高低不等于显著差异。
- 【铁律】核对实际有效覆盖，再说明完整评估集合或有效子集，不预设必须删到共同子集。实际使用共同有效子集时，写清纳入条件、n of N 与排除原因；缺失、无效与不适用分开，不能只留成功输出。
- 【铁律】实测案例与示意案例分开，说明选例依据。个例用于解释过程，不证明总体排名或部署效果；被测模型得分高，也不能证明 benchmark 更好。
- 【铁律】全局失败组成、某场景发生率与条件子集表现分别给对象和分母；不能将不同分母的比例直接相减，也不能用局部失败诊断冒充整体差距的因果解释。
- 【铁律】区分初始判分、人工复核标签与最终得分。一致性写清比较对象、范围与分母；标签一致率不等于独立准确率，也不能证明没有偏差。
- 【铁律】Metrics 用一个紧凑自然段：先说明指标类别和适用对象，再按 1) 加粗指标名、2) 加粗指标名逐项定义；Models 或 Baselines 另写。每项交代定义、方向、单位、分母和汇总，不把指标分成零散无编号小节。
- 已有初始与复核记录时，可分析标签修改方向、模型分布和得分或排名敏感性。协议约束不等于已测得去偏效果，未测试的偏差不写成已证明。
- 评价器的准确标识、参数和输出限制集中放在一个可定位的设置块；正文给必要角色与引用，不反复复制全部配置。实际材料与判分版本必须对应。

#### 指标定义

**English 教学改写**

To test whether evidence notes improve citation support, we evaluate multi-turn questions about static English manuals. Human raters check each factual answer sentence against its cited passage using a shared rule. A sentence without a citation counts as unsupported. For each question, citation support is the fraction of factual sentences supported by their cited evidence; higher is better. We average these per-question fractions rather than pooling sentences across questions. Answers with no factual sentences are reported separately as not applicable, together with their count.


**中文译文**

为检验证据笔记能否提高引用支持率，我们评价针对静态英语手册的多轮问题。指标。人工按同一规则检查每句事实能否由所引片段支持。没有引用的句子按不支持计。对每个问题，引用支持率是获所引证据支持的事实句比例，越高越好。我们对各问题的比例取平均，不把所有问题的事实句混在一起计算。没有事实句的回答单列为不适用，并报告数量。


**高亮与旁批**

1. **To test whether evidence notes improve citation support / 为检验证据笔记能否提高引用支持率**：问题接回方法作用。先说这组评价要检验什么，不能从设备型号开始。
2. **Human raters check each factual answer sentence / 人工按同一规则检查每句事实**：谁判什么。人工、判定单位与证据对象都可定位。完整说明和一致性核验另给实际记录。
3. **A sentence without a citation counts as unsupported. / 没有引用的句子按不支持计。**：缺失也进入口径。缺引用不能从分母中静默排除，否则少给引用反而可能得高分。
4. **We average these per-question fractions rather than pooling sentences across questions. / 我们对各问题的比例取平均，不把所有问题的事实句混在一起计算。**：说明怎样汇总。先按问题计算再平均，与把所有句子合并计算不同；长回答不会只因句子多而权重更大。
5. **reported separately as not applicable / 单列为不适用**：定义不能评分的情形。没有事实句时，比例无定义。不能自动算零或算满分，还要报告数量。

#### 结果解释与局限

假设教学段落，非论文原文或实测结果。

**English 教学改写**

However, the current comparison changes both quote organization and the amount of constraint information provided to the generator. **中文译文**

**高亮与旁批**

1. **is consistent with more explicit use of document evidence / 与更明确地使用文档证据这一解释相符**：先说结果的意义。consistent with 表示解释与观察相符，尚未声称已证明机制。意义仍限于来源支持。

3. **The comparison therefore cannot identify which change accounts for the gain. / 因此，这个比较不能判断哪项改变带来了收益。**：However 之后要得出真实限制。前句说明两项条件同时变化，这句限定归因范围。Therefore 接住原因，不是只在句首加一个词。
4. **cross-language questions and frequently updated documents remain untested / 跨语言问题与频繁更新的文档尚未检验**：范围要具体。语言变化和文档更新是两个尚未测的设置。写出来，比一句 limited generalizability 有用。

### 3.9 局限性

用一个自然段写清两项与任务相关的具体边界。

#### 本节原则

- 【铁律】本套 CS 写作约定：Limitations 全节只写一个自然段，用 First, 和 Second, 引出两点，不另起段、列条目或加小标题。官方格式与当前用户要求优先。
- 【铁律】每点先用 although 简短说明已完成的有据工作，再给具体的特殊或长期边界；已有措施不能写成解决了尚未验证的问题。
- 作者行动用 we；贡献和实现细节简写，重点放在仍需讨论的具体对象及其与本文任务的关系。

### 4.8 开源整理

先写清允许处理的文件。中文界面、接口字符串、业务路径也可能影响运行，不能一键全换。

**中文提示词**

```text
只处理我指定的文件：<文件或目录>。
把中文注释、文档字符串和使用说明译成英文，保留解释代码所需的注释，删除版本更改流水账。把注释和文档中的个人信息、内部地址、机器绝对路径改成通用说明、相对路径和可运行的例子。保留必要的作者署名、引用与许可证信息。
保持算法、控制流程、变量名、接口、参数和数据不变。不要自行翻译程序输出、异常消息、协议字段或其他可执行字符串；若文档字符串被程序读取，也先报告影响。
疑似密钥、私有数据或运行时配置不要贴出原值。列出文件位置和处理建议；若替换会影响行为，先停在该处，说明需要什么决定。去秘检查也覆盖计划发布的样例、配置、日志和压缩包；若还发布 Git 历史，另查历史内容。
示例：文档中的机器路径改为 data/example.json，并说明从项目入口定位；只改说明，不改程序的路径解析逻辑。密钥示例使用 YOUR_API_KEY，不写真实值。
交付修改差异、处理过的内容类型、未解决项和实际验证结果。没有跑过的检查不要说通过；发现真实秘密时不要发布，先报告位置和处置需求。
```

依据：minimal-code-layout · 作者指定的翻译与去秘范围 · [对应铁律与完整提示词](https://github.com/Da1yuqin/StarPaper/blob/main/data/guide.json)
