## 写在前头

cs-paper-writing 按章节加载写作规则。starpaper-figures 支持方法图、案例图和实验图。

这里整理我的论文写作与修改经验，供学术讨论。本人并非领域权威，内容可能有误。

网页开源，支持批注。欢迎纠错、讨论写法，我会据此修订。

*多数例子来自本人、本人参与或熟人的论文。其余选自公开论文，均附出处。用于研究时，请引用对应原论文。*

2. 梳理参考论文的章节职责、顺序和输入输出。

   读取 cs-visuals，精修图形时另读绘图 skill。
4. 列出各节标题、任务、证据和篇幅。

### 1.2 正文结构

提醒小伙伴：实验要充足，正文篇幅要用足！我的排版目标是：***最后几页每页至少一项实验及其分析。正文一定要写满投稿限制的最大内容。例如 limit 8 页，一定要写满 8 页***。补充必要的对照、消融与边界分析。这是个人经验，须按研究内容与会议要求调整。

师兄说：“把审稿人当作魔鬼。”先问自己：实验够吗？比较公平吗？结论有证据吗？其他章节同样检查，别留解释缺口。关键实验缺失、论证不足，都可能导致拒稿。

先用 [Codex 写作 skill](#writing-skill) 生成初稿。生成后，按[正文精修](#refine)逐节修改。

<details><summary>参考大纲：按论文类型选结构</summary>

#### 论文大纲与章节衔接

先按核心贡献选论证主线，再排全文章节。诊断驱动论文须先用证据确立发现。不能只换引言标题。下列三套仅供参考，段落、模块与节号按需调整。

| 论文类型 | 引言的论证顺序 | 正文的展开顺序 |
| --- | --- | --- |
| 方法论文 | 背景与回顾 → 局限 → 设计 → 发现 → 贡献总结 | Related Work → Method → Experiments → Conclusion |
| 基准与数据集论文 | 能力与评价 → 缺口及建设障碍 → 产物与设计 → 发现 → 贡献总结 | Related Work → Construction → Evaluation → Conclusion |
| 诊断驱动的改进研究 | 能力判断 → 质疑与发现 → 瓶颈 → 设计 → 验证 → 贡献总结 | Diagnostic Analysis → Method → Experiments → Related Work → Conclusion |

<a id="structure-method"></a>
<details><summary>方法论文：大纲与章节衔接</summary>

核心贡献是新方法或系统设计。先说已有局限，再说对应设计。最后检验整体效果与设计作用。

<a id="draft-paper-outline"></a>
#### 方法论文：局限 → 设计 → 验证

方括号填对象、动作与证据。节名和编号仅作示意。图示串行方法；并行或反馈须画出实际关系。

Abstract：概括问题、贡献与关键发现。主张、术语和范围与正文一致。通常待主要结果确定后定稿。

**1 Introduction**

为什么要研究[问题]？已有路线哪里不足？本文怎样处理？实验发现什么？

- **背景与比较**：交代领域目标、已有进展与比较依据。前两段可穿插或合并。

- **具体局限**：However, [limitation] ... 说明限制条件。解释现有路线为何达不到[目标]。

- **核心工作与设计**：To address these limitations, we propose [name], a [亮点与用途]. 再用 For [limitation], we [设计与作用] 逐项对应。

- **结果与贡献总结**：先概述主要发现。再以 In summary, our contributions are: 引出贡献列表。

↓ 已有局限的比较依据在哪里？

**2 Related Work**

按共同任务或机制分组，说明真正相关的路线怎样工作。

- **每个主题收尾**：However, [与引言一致的具体缺口]. To address this gap, we [动作] [对象] based on [真实原则]. This enables [实际应用], addressing [同一缺口]. 依次写缺口、做法、应用及其作用。

↓ 哪些设计处理这些局限，为什么这样设计？

**3 Method**

Overview：核心思想是[设计思路]。For [局限一], we [设计 A 的关键动作]，产生[中间产物 a]。[设计 B]用它处理[局限二]，产生[b]。[执行流程]将这些设计落实为[最终输出]。按实际节名与节号介绍各节作用。

↓ 概括各小节的职责与交接

3.1 Problem Formulation：定义输入、输出、目标与约束。分别说明训练、推理和评价可见的信息。已有定义较长时，另设 Preliminaries。

- **3.2 [设计 A 的具体名称]**：[任务输入 x] → For [局限一], [关键操作与依据]. → [中间产物 a]

- **3.3 [设计 B 的具体名称]**：[a] + [必要附加信息] → For [局限二], [关键操作与依据]. → [中间产物 b]

- **3.4 [训练、推理或评价流程]**：[b] + [执行所需材料] → 按论文类型写优化、运行或评分流程。 → [最终输出 y]

串行示意：x → A → a → B → b → 执行流程 → y。箭头传递实际对象。模块与训练步骤按需设置。

↓ 怎样检验整体目标与各项设计的作用？

Overview 说明各小节怎样组成完整方法。训练与推理的信息分开画。评分参考不能混入模型输入。

**4 Experiments**

按研究问题组织证据。先给设置，再给主结果与针对性检验。

- **4.1 Experimental Setup**：交代数据版本与划分。Metrics 写定义、方向、分母与汇总方式。Baselines 写来源及可比条件。Implementation 写训练／推理、调参、预算与重复设置。解释误差条或区间。人工或模型评分另写协议与核验。

- **4.2 Main Results**：回答整体研究问题。实际结论 → 关键对照与图表 → 含义及范围。

- **4.3 Design Validation（按需）**：针对[设计为何处理局限]安排受控删除、替换等对照。写明变化因素、保留条件与耦合差异。基准论文可检验数据、判据或评分协议。

- **4.4 Further Analysis（按需）**：按主张选择泛化、敏感性、代价、错误或解释分析。每节回答一个问题。个例展示过程，频率结论需总体统计。

↓ 结果支持了什么，哪些解释和范围仍未得到验证？

**5 Discussion and Limitations**

说明发现与已有研究的关系。区分观察、可能解释和已验证机制。写清假设、覆盖范围、失败条件及影响。

- **按实际内容与投稿要求**：讨论可与分析合并；Limitations 可单列。适用时说明数据授权、人类参与、隐私与风险。

↓ 在实际证据范围内，开头的问题得到什么答案？

**6 Conclusion**

回答研究问题，概括已验证的贡献与发现。保持同一证据范围，不新增结果或设计。

References 支撑已有工作、定义与外部事实。Appendix 收录完整设置、算法或提示词。补充结果与复核材料也放附录。核心证据须留在正文。局限、伦理及其他声明按投稿要求安排。

<details><summary>基准与数据集论文：大纲与章节衔接</summary>

核心贡献是数据、基准或评价协议。先明确评价缺口，再讲构建与评分。最后分析受测系统的表现。

<a id="draft-benchmark-outline"></a>
#### 基准与数据集论文：评价缺口 → 构建 → 测评

核心产物是数据、基准或评价协议。先定义并构建评价对象，再报告表现与诊断。不必虚构新模型。

Abstract：概括问题、贡献与关键发现。主张、术语和范围与正文一致。通常待主要结果确定后定稿。

**1 Introduction**

为什么现有评价还不能回答[能力问题]？本文提供什么输入、判据或协议？

- **背景与已有评价**：回顾能力与评价方式。比较同一目标、输入与判据。“未报告”不写成“没有”。

- **评价缺口与建设障碍**：先说哪些[行为]无法区分。再说收集[数据]或构建[判据]为何困难。两类问题分别对应设计。

- **产物与对应贡献**：To address these limitations, we propose [name], a [亮点与评价用途]. For [评价局限], we [数据或判据设计].

- **测评发现与贡献总结**：先概述真正有信息量的发现，再总结数据、评价设计及发现的独立贡献。

↓ 哪些相关路线支持这个比较？

**2 Related Work**

按任务或评价目标归类，说明已有输入、判据和覆盖范围。

- **每个主题末尾**：However, [与引言一致的具体缺口]. To address this gap, we [动作] [对象] based on [真实原则]. This enables [实际应用], addressing [同一缺口]. 依次写缺口、做法、应用及其作用。

↓ 对应的缺口怎样落实为评价设计？

**3 Benchmark Construction**

Overview：评价[目标能力]需要[输入与判据]。先将[来源材料]构造成[案例]。再据此定义[评价准则]。受测系统生成[回复]。评分者按[证据与准则]评估。后文分讲案例、判据与评分协议。若提出辅助方法，另讲其作用。

↓ 概括各小节的职责与交接

3.1 Problem Formulation：定义任务、系统输入 x、回复 y 与参考证据 r。再定义评分目标。区分系统与评分者可见的材料。

- **3.2 Data / Case Construction**：[原始来源材料] → 说明来源、筛选或采样、标注与划分。产物须回应前文的评价缺口。 → [案例 x 与参考证据 r]

- **3.3 Evaluation Criteria**：[案例 x、参考证据 r] → 定义判据及制定依据。说明怎样区分目标行为、可接受答案与错误。 → [准则 c]

- **3.4 Response Assessment**：[回复 y] + [x, r, c] → 说明评分者、步骤、汇总与核验。此处定义协议，下一章执行测评。 → [评分与报告格式]

资料流：来源 → 案例 → 准则 → 评分协议。受测系统接收 x，生成 y。评分者结合 y、r 和 c 评分。评测参考不得泄漏到系统输入。

↓ 用这套评价实际看到了什么，它是否测到了目标能力？

独立辅助方法可放构建章，或另设节。说明它与评价目标的关系，没有则不加。区分判据制定、评分执行与结果分析。

**4 Evaluation**

先给可比设置，再概述主要发现。随后分析差异、失败与评价边界。

- **4.1 Evaluation Setup**：交代数据划分、受测系统与运行条件。补充指标、评分协议与不确定性。评分核验随评分说明就近呈现。

- **4.2 Main Results**：To answer [研究问题], we evaluate [系统]. 先给发现，再给关键比较与支持范围。不要从模型名单或分数排名讲起。

- **4.3 Evaluation Validation（按需）**：用有区分力的对照检验是否测到[目标]。必要时核验判据或评分。一次总分比较不能证明评价有效。

- **4.4 Scenario / Error Analysis**：按条件或失败模式组织分析。个例解释过程，普遍性与频率需总体统计。

↓ 哪些结论得到支持，哪些条件仍未覆盖？

**5 Conclusion**

回答评价问题，概括产物与主要发现。覆盖范围不代表真实使用频率。

**Limitations / Ethics Statement**

说明来源、任务覆盖、判据与评分边界。按实际研究交代授权、隐私或风险。

References 支撑已有工作、定义与外部事实。Appendix 收录完整设置、算法或提示词。补充结果与复核材料也放附录。核心证据须留在正文。局限、伦理及其他声明按投稿要求安排。

</details>

<a id="structure-diagnostic"></a>
<details><summary>诊断驱动的改进研究：大纲与章节衔接</summary>

先用实验揭示问题、定位瓶颈。再提出并验证改进。诊断是独立贡献，方法与验证都须回应它。

<a id="draft-diagnostic-outline"></a>
#### 诊断驱动的改进研究：发现问题 → 定位瓶颈 → 改进验证

先确立诊断，再引出方法。后续验证复用诊断条件与观察维度。仅有主结果表，无法回答最初的问题。

Abstract：概括问题、贡献与关键发现。主张、术语和范围与正文一致。通常待主要结果确定后定稿。

**1 Introduction**

已有成绩是否代表[目标能力]？诊断发现了什么？瓶颈在哪？本文怎样回应？

- **背景与能力判断**：介绍已有路线及成绩，说明这些成绩通常被理解成什么能力。

- **质疑与诊断发现**：However, [能力质疑]. 说明[受控诊断]如何检验它。紧接关键观察。

- **瓶颈与设计判断**：用进一步对照区分解释。说明有据的[瓶颈]为何需要[设计思路]。

- **方法、验证与贡献总结**：概述对应设计与主要验证。最后总结诊断、方法与验证贡献。

↓ 先把质疑变成可检验要求，再给诊断证据。

**2 Diagnostic Analysis**

先证明问题存在，给出瓶颈依据。再介绍改进方法。

- **2.1 Testable Hypothesis**：把[目标能力]转成在[受控条件]下应该满足的可检验要求。

- **2.2 Diagnostic Data and Protocol**：写清改变项与固定项。说明混淆因素和比较预算如何控制。

- **2.3 Findings and Diagnostic Controls**：报告目标表现与过程症状。用有区分力的对照检验解释。相关变化不直接等于因果机制。

↓ 诊断指出的瓶颈，成为方法每项设计的理由。

**3 Proposed Method**

Overview：诊断表明[瓶颈 A]妨碍[目标]。For [瓶颈 A], we [设计 A]，产生[a]。[设计 B]用它处理[瓶颈 B]，产生[b]。[训练或执行流程]将它们落实为[y]。先说设计依据，再讲输入输出与依赖。

↓ 概括各小节的职责与交接

3.1 Overview / Problem Formulation：定义必要对象及训练、推理的输入输出。沿用诊断章的定义，不再重复。

- **3.2 [Design A]**：[任务输入 x] → For [诊断瓶颈 A], [设计动作与依据]. → [产物 a]

- **3.3 [Design B]**：[a] + [必要信息] → For [诊断瓶颈 B], [设计动作与依据]. → [产物 b]

- **3.4 [Training / Execution]**：[b] + [执行材料] → 按方法给训练目标或执行流程。不强加训练步骤。 → [最终输出 y]

各项设计对应诊断中的具体瓶颈。箭头传递实际对象。模块数量与关系按实际方法调整。

↓ 既验证主任务表现，也复测原诊断。检查最初的失败是否缓解。

诊断中的假设、对照与发现须能独立读懂。引出方法不能代替验证问题。

**4 Experiments**

围绕诊断与设计安排验证。主任务表现、诊断复测与过程证据各有分工。

- **4.1 Experimental Setup**：交代数据、基线、指标与公平比较条件。诊断章已有协议只补新增项。

- **4.2 Main Results**：回答改进方法在主要任务上是否有效，说明例外与范围。

- **4.3 Diagnostic Robustness**：复用第 2 章的诊断条件，检验原有失败是否缓解及其范围。

- **4.4 Process / Mechanism Analysis**：复用诊断维度，检查过程变化是否支持瓶颈解释。机制主张需有区分力的检验。

- **4.5 Ablation / Alternative Explanations**：检验关键设计。控制预算、提示等与主张相关的替代解释。

↓ 比较这些证据是否共同支持原来的设计判断。

**5 Related Work**

围绕已明确的问题与设计比较相关路线。主题末尾用 However 指出局限。紧接本文处理方式。

- **位置选择**：可放在实验后，也可放在引言后。前置便于先解释概念，后置突出诊断主线。

↓ 回到最初的能力问题，收束诊断与验证。

**6 Conclusion**

回答[目标能力问题]。概括诊断发现、对应设计与证据范围。

**Limitations / Ethics Statement**

说明未解决的问题与适用范围。与引言、诊断及结论一致。

References 支撑已有工作、定义与外部事实。Appendix 收录完整设置、算法或提示词。补充结果与复核材料也放附录。核心证据须留在正文。局限、伦理及其他声明按投稿要求安排。

</details>

只有实证发现、没有改进方法时，可用以下结构。Introduction → Study Design → Results → Robustness / Further Analysis → Discussion → Conclusion。引言顺序：问题 → 证据缺口 → 研究设计 → 发现 → 贡献总结。删去改进方法及其消融。Related Work、局限与声明按论证及投稿要求安排。

</details>

<a id="refine"></a>
## 2. 正文精修

按论文顺序精修正文与图表。先读要求，再填模板。


<a id="general-rules"></a>
### 2.1 全文规范

“铁律”是本套 skill 的必守要求，其余为建议。官方规定与当前作者要求优先。三项贡献、Limitations 两点格式均属本套约定。它们不是所有会议的规定。句式与组织模板仅供参考。

#### 篇幅与版面：充分呈现证据

- **【铁律】遵守当轮篇幅要求：**按会议上限和当前稿件目标安排篇幅。要求写满时，补足证据、比较和解释。明显偏短，容易让人怀疑实验与分析不足。不要凑页注水，也不要跨论文套页数。

- **实验与分析就近呈现：**结果、图表与解释就近排。核心证据留在正文，篇幅按分析需要分配。

- **【铁律】保留支撑结论的证据：**保留支撑结论的实验分析、必要条件和关键比较。超页先删重复和无关背景。再压缩 Related Work 与常规方法介绍。

- **【铁律】保持官方模板：**分别核查正文、文献与附录的页数。不得改字号、行距、字距或页边距凑页。以最终 PDF 为准，不能只看源码长度。

- **【铁律】图表与正文一致：**统一名称、符号、单位、数值和范围。图表就近引用，caption 解释读法。改图表后回查正文。

#### 逻辑：句子承接与对象一致

- **先说为什么值得做：**先说已有做法在哪些条件下不足。再说本文改了什么、为何有用、证据是什么。

- **【铁律】不虚构章节依赖：**章首承接具体问题或产物。确有后续用途，章末才交代去向。不把并行写成串行。Related Work 小节直接进入内容。Intro 以贡献列表结束。Conclusion 不预告不存在的下一步。

- **【铁律】钩子连接真实关系：**前句建立对象或前提，后句推进判断。However 表示转折，Therefore 从证据归纳。Specifically 展开判断，Then 表示真实先后。举例用 For example 或 For instance。连接词不能代替依据。

<a id="standard-alignment"></a>
![铁律：前后对应。边牧指出星形缺口，魔法猫制作对应星星，小龙检验是否匹配。](../assets/refine-alignment-comic.png)

设计回应引言的问题，实验检验对应设计。

#### 语言：完整判断与句长

- **用具体操作替代空泛评价：**用具体操作替换 powerful、comprehensive 等空评价。

- **【铁律】短句，完整动作：**每句一个主要判断，不用分号续长句。最终 PDF 中，常用双栏窄栏句子最多 3 行。单栏约 1.5 行；本稿另有要求时从其规定。保留动作、条件与承接，不缩字体或改模板。

- **【铁律】正文写完整句子：**正文写完整句子。不用加号、斜杠、与号或箭头代替文字。英文不用破折号插入解释。复合词连字符、数学、单位和图连线保留。

- **同级小节篇幅相称：**任务相近，篇幅尽量相称。过长先查重复，复杂内容分段。

- **【铁律】近距离用词去重：**检查同句、相邻句和短段的用词重复。包括实义词、词根和起句。删冗余，不靠同义词掩盖重复。必要术语保留。

#### 术语：首次定义与名称一致

- **【铁律】术语首次解释：**写清对象和用途，不让读者到后文找定义。

- **【铁律】符号首次定义：**符号首次出现就定义对象、单位和下标。计算量再说明来源与算法。删除未使用的符号。

- **【铁律】同一对象同一称呼：**同一对象使用同一名称。代词应指向唯一、明确且就近的对象。含混时改用短名称，清楚的代词保留。

- **【铁律】贡献修饰词：**先写贡献对象与动作，修饰词不能代替贡献。tailored、expert-confirmed 等词需有证据。

- **命名发现立即解释：**用准确、好懂的短名概括发现。通常不超过四个英文词。紧接定义与证据，不能只给名称。

#### 主张：证据与适用范围

- **【铁律】保留结论条件：**写清任务、模型、范围和分母。有限测试不推广到所有场景。

- **【铁律】观察与原因分开：**先报告现象，再讲可能原因。匹配对照支持后才归因。

- **结果首句写发现：**结果段先给发现，再给图表、关键比较和意义。不要把结论藏在设置后面。

- **【铁律】数字与统计口径准确：**数字用阿拉伯数字，并能回查最新记录。子集给 n of N、单位与版本。区分百分比与百分点、宏平均与微平均。未知不填 0，不换分母或单位夸大结果。

### 2.3 摘要

一个自然段串起背景、多个局限、对应设计和实验亮点。

#### 本节原则

- 【铁律】一个自然段：背景 → 局限 → 对应方法 → 实验数字与结论。长度服从会议要求。
- 局限逐项写，数量按实际问题调整。首次出现的关键词用粗斜体，不加粗整句。
- 【铁律】逐项用 For [具体局限], we [实际动作与作用]. 引出解法。同一问题沿用同一名称。
- 优先给支持贡献的实测数字、对照与发现。发现型可先概括发现，再给数字。
- 【铁律】摘要与引言的问题、设计、名称及数字一致。评价范围和结论也一致；摘要压缩，引言展开。

<a id="annotated-abstract"></a>

#### 摘要模板

一个自然段写完问题、解法与实验亮点。

**English 填空模板**

[Research task] requires [capability needed in practice]. Existing methods in [research line] face ***[limitation A]*** and ***[limitation B]***, which hinder [specific goal]. We introduce [Method], a [concrete artifact and its purpose]. For [same limitation A], we [design A and its function]. For [same limitation B], we [design B and its function]. Experiments on [evaluation scope] show that [verified quantitative result with its metric, unit, and comparison reference]. Further analysis reveals [key experimental finding], showing [what this finding answers about the research question].


**高亮与旁批**

1. **[Research task] requires [capability needed in practice].**：背景：任务与能力。交代具体任务与能力需求。为下句的局限提供比较标准。
2. **Existing methods in [research line] face [limitation A] and [limitation B], which hinder [specific goal].**：局限：具体障碍。A、B 填具体障碍。关键词用粗斜体。按实际问题增删，不凑数量。
3. **We introduce [Method], a [concrete artifact and its purpose].**：贡献：对象与用途。先写提出什么、用于什么。下句再展开设计。
4. **For [same limitation A], we [design A and its function]. For [same limitation B], we [design B and its function].**：解法：回应局限。两个 For 分别接回 A、B。后半句填对应设计与作用。
5. **Experiments on [evaluation scope] show that [verified quantitative result with its metric, unit, and comparison reference].**：实验：数字与对照。填最能支持贡献的实测数字。方法型可写相对基线的提升。评价型可写占比或得分差距。标明范围、指标与单位。
6. **Further analysis reveals [key experimental finding], showing [what this finding answers about the research question].**：结论：发现与意义。填关键发现及其意义。如适用条件、解决的困难。发现型可先讲发现，再给数字。

### 2.4 引言

建立问题，解释设计，再用发现与贡献概括全文。

#### 本节原则

- 先定顺序：领域与回顾 → 局限 → 设计 → 发现 → 3 条贡献。前两部分可合并、交错或拆段。
- 【铁律】段首承接前文对象。转折接不足，目的接问题，归纳接证据。
- 【铁律】每项局限写清原因与后果，并给对应设计。Method 展开设计，Experiments 检验作用。结论回答同一目标。
- 方法名后立即写产物与用途，再逐项回应局限。引言解释设计理由，实现细节留到 Method。
- 实验段先概述发现，再给关键数字与分析。与摘要及正文实验结论一致。
- 【铁律】贡献固定 3 点：整体工作、关键设计或证据、实验发现。按类型填真实贡献，不虚构机制或诊断。已讲清的问题与解法无需重复局限标签。
- 【铁律】引言只引用本节图表。不要提前指向后文章节、公式、方法图或附录。保留文献引用与有据结论。
- 【铁律】正式命名对象在引言中每次出现用斜体。每个对象最多强调性加粗一次，含贡献列表。普通术语不机械斜体。

<a id="figure-mainfig"></a>
#### Mainfig：引言主图

说明研究问题与本文改动，概述贡献。不承担全部方法细节。

##### Stage 1 · 确定问题与改动

- 先用一句话定主张，再列必要输入、缺口、改动和输出。删除无关节点，通常不超过 5 个环节。
- 方法型用同一问题对照旧做法与本文改动。发现型用实测观察提出问题。注明数据、条件与比较对象。
- 【铁律】分清概念示意与实测结果。没有实验依据，不画提升曲线或通过标记。

##### Stage 2 · 对齐比较与读图顺序

- 旧做法与本文设计分两行或两面板。共享输入的位置与名称，并对齐改动处。
- 保留具体输入片段与产物，不只写 Input、Model、Output。为短标签留空间，图注不抄图中文字。
- 优先用单栏简图，通栏可从扁宽布局起稿。按实际栏宽排字，再定框大小。不把复杂 Framework 缩成 Mainfig。

##### Stage 3 · 突出改动并验收

- 只突出本文改动及对应问题，其余结构用中性色。高亮较多时保持白底。
- 图标旁写对象名，未知项用文字标明。高亮与线型均有释义，不靠颜色暗示好坏。
- 按最终尺寸，检查能否独立读懂问题、改动和输出。读不懂就补信息或重排，不加装饰。

To address these limitations, we propose \textit{[benchmark or dataset name]}, a [verified source or distinguishing design] for [evaluation purpose]. For [data construction obstacle], we construct [data contribution] from [verified source] using [documented selection or collection rule]. For [specific evaluation limitation], we [evaluation contribution and action] to measure [capability linked to the earlier gap]. The tested system receives [task input], while [evaluation evidence or criteria] is used by [evaluator] to assess [system output]. These components support [supported evaluation capability] within [coverage boundary].

These results indicate [bounded implication] and leave [remaining question] unresolved.

先给发现，再解释命名现象的含义。诊断回答原问题，不扩大为未验证的机制。

**贡献总结**

```latex
In summary, our contributions are:
\begin{itemize}
    \item We introduce \textit{[benchmark or dataset name]}, which supports [evaluation task] with [verified coverage and core components].
    \item We propose [construction or evaluation design] based on [verified source or principle] to [address the specific evaluation difficulty].

\end{itemize}
```

<a id="intro-body-map"></a>
#### 引言如何贯穿全文

引言提出问题。相关工作给依据，方法给设计，实验给检验。讨论与结论说明意义和范围。

方括号填同一组对象。同色高亮与箭头表示对应关系。句数、段数与局限数量不固定。

- **Q · 研究问题：**全文回答同一问题。

- **L → M → E · 局限、设计与检验：**哪项设计处理哪项已有不足？用什么证据检验？

- **D · 实施困难：**实施本文研究的困难。必要时单独展开。

- **B · 本文剩余局限：**说明本文解决到哪一步。与前人局限 L 分开。

**A · 背景与已有研究**

[已有研究]已说明[已知能力或发现]。这些结果支持[应用目标或进一步研究]。

句首钩子：`These findings motivate [the research question].`

- 相关工作 · 核实已有起点：写清[已有路线]的实际能力、输入和适用条件。附原论文依据。
- 方法 · 区分已有与新增：说明哪些能力来自已有方法，本文新增了什么设计。

承认并引用已有能力。不把它们写成本文贡献。

**Q · 研究问题**

[研究背景或实践需求]提出[具体研究问题 Q]。

句首钩子：`To answer [the specific research question], we ...`

- 方法 · 任务定义 · 定义对象与目标：将 Q 对应到[研究对象]与[任务定义或变量关系]。给出[可观测量]。系统任务再写输入、输出与约束。
- 实验 · 研究问题 · 给出检验方式：用[数据与比较条件]和[对应指标]检验 Q。
- 结论 · 回答开头：依据实际结果，在[已研究条件]内回答 Q。

任务、指标与结论针对同一对象和能力。代理指标改善，不代表未经测量的应用收益。

**L1 → M1 → E1 · 已有局限与对应解法**

However, [已有路线]在[具体范围]存在[局限 L1]，因而妨碍[目标 Q]。For [局限 L1], we [设计 M1 的具体动作].

句首钩子：`For [limitation L1], we [specific design action].`

- 相关工作 · 主题收尾 · 给 L1 比较依据：However, [L1：现有路线在具体条件下无法完成什么及其后果]. To address this gap, we [实际动作] [对象] based on [真实原则]. This enables [实际应用], [有依据的 -ing 动词] [前述同一问题].
- 方法 · M1 · 解释为什么这样设计：[M1]针对 L1 的哪项原因？采取什么操作？产物供后续怎样使用？
- 实验 · E1 · 检验原动机：用[能检验 M1 作用的对照 E1]检查[与 L1 对应的指标或行为]。

三处沿用同一局限名称与比较范围。“未报告”不写成“没有”。整体系统对比不能证明单项设计的收益。

**L2 → M2 → E2 · 另一项独立局限（按需）**

此外，[独立局限 L2]影响[另一必要能力]。For [独立局限 L2], we [设计 M2 的具体动作].

句首钩子：`For [limitation L2], we [specific design action].`

- 相关工作 · 另一主题 · 说明 L2 有何不同：给 L2 的依据，紧接 M2。不要换词重复 L1。
- 方法 · M2 · 交代独立作用：说明 M2 使用什么输入，怎样满足[与 L2 对应的要求]。
- 实验 · E2 · 给对应检验：E2 检验[与 L2 对应的能力]。结果段沿用同一问题，解释实际发现。

有独立不足才增加此项。不为凑“两项局限”重复问题。

**D · 实施困难（按需）**

[实施困难 D]限制[研究任务]。这会阻碍[必要步骤]。

句首钩子：`Establishing [the required artifact] requires [specific step].`

- 方法 · 构建或研究设计 · 给可执行解法：说明实际来源、选择规则、操作与产物怎样处理 D。
- 附录 · 补可复核材料：提供[与 D 的解法对应的协议、配置或材料]，并从正文定位。

D 是实施困难，L 是前人局限，两者不同。如实交代来源与权限等影响判断的信息。

**M · 核心设计与贡献**

To address these limitations, we propose [name], a [核心亮点与用途]。For [同名局限], we [核心设计的具体动作].

句首钩子：`For [named limitation], we [concrete contribution].`

- 方法 · Overview · 展开贡献与依赖：先说核心思想与每项设计的作用。再概括各节输入、操作与输出。
- 框架图与图注 · 显示同一操作关系：图中对象、名称与方向须与正文一致。按实际画串行、并行或反馈。
- 实验 · 设置与设计检验 · 固定能判断作用的条件：比较条件须对应[要检验的设计作用]。说明固定项与无法对齐的差异。

引言点明贡献，方法解释实现，实验提供检验。产物、流程与效果分别写清。

**E → Q · 主要发现**

To answer [Q], we evaluate [研究对象] under [条件]。实验发现[主要结论 E]，回答了[Q 的哪一部分]。

句首钩子：`To examine [the motivated capability], we compare [objects].`

- 实验 · 主结果与分析 · 先结论，再证据：报告 E 对应的关键比较、图表、指标口径和不确定性。
- 实验 · 回扣动机 · 解释回答了什么：说明 E 是否支持[原设计目标]。改善、无支持或失败，均回答同一问题。
- 摘要与引言 · 压缩同一发现：摘要压缩 E，引言概述 E。名称、数值、对象和范围与实验一致。
- 讨论 · 限定解释：区分观察到的差异、可能原因与已验证机制。

实验结论回应最初动机。无受控检验，不作因果归因。案例不代替总体频率。

**C / B · 贡献与结论范围**

本文提供[新增贡献 C]，揭示[实际发现]。结论限于[已验证范围]。仍有[本文剩余局限 B]。

句首钩子：`Within [the evaluated conditions], [supported conclusion].`

- 讨论与局限 · 解释 B 的影响：说明[未覆盖条件或假设 B]怎样限制结论。未测试不等于已失败。
- 结论 · 闭合 Q：回答 Q，概括已验证的贡献与发现，保留同一范围。
- 摘要与引言 · 反向校准主张：证据只支持[有限范围]时，主张都缩至该范围。包括摘要、引言与贡献句。

L 是前人不足，B 是本文边界。限制核心主张的 B 须随该主张说明。不必将全部局限塞进引言。

L1 → M1 → E1 → Q：[具体局限] → [对应设计] → [设计作用的检验] → [对研究问题的回答]。

其他主张：数据质量、效率、泛化或机制也需对应证据。按实际贡献补充，不能只重复钩子。

**结果回写**：实际发现及范围 → 摘要、引言 → 讨论与结论。结果或证据范围改变，对应主张也须更新。

### 2.5 相关工作

按主题回顾已有工作，段末依次写局限、本文做法和应用。

#### 本节原则

- 按任务、机制或评价目标分主题，标题独占一行。主题内先归类能力，再比较缺口。
- 【铁律】每段末 3 句固定，顺序不能交换。However 写局限，we 写做法，This enables 写应用与作用。
- 【铁律】段末局限与引言对应。区分做法、应用及解决的问题。相邻主题处理不同不足。
- 引用紧跟判断，承认已有能力。未报告不等于不存在，未比较不等于失败。

<a id="annotated-related"></a>

#### 相关工作主题段模板

每段依次写：已有工作、局限、做法、应用。

**English 填空模板**

[Research topic] studies [task or goal]. Methods in [family A] use [mechanism A] to [established capability A] [citations]. Methods in [family B] support [different capability B] through [mechanism B] [citations]. However, [a complete clause stating the limitation and its consequence]. To address this gap, we [action] [research object] based on [method or principle]. This enables [actual application], [evidence-supported -ing verb] [the same problem stated in the gap].


**高亮与旁批**

1. **[Research topic] studies [task or goal].**：小节主题。填本组工作的任务或机制。主题标题另起一行。
2. **Methods in [family A] use [mechanism A] to [established capability A] [citations]. Methods in [family B] support [different capability B] through [mechanism B] [citations].**：归类回顾。归类写已有能力与共同思路。引用紧跟判断。
3. **However, [a complete clause stating the limitation and its consequence].**：倒数第三句：局限。However 后写完整判断。说明谁在什么条件下做不到什么。再写这会妨碍哪个目标。
4. **To address this gap, we [action] [research object] based on [method or principle].**：倒数第二句：做法。主语用 we，填动作、对象与依据。做法直接回应上一句局限。
5. **This enables [actual application], [evidence-supported -ing verb] [the same problem stated in the gap].**：末句：应用与作用。前半句填支持的任务。后半句用 -ing 接回同一问题。动词强度取决于证据。

### 2.6 方法

先解释设计为什么有用，再用输入、操作和输出展开。

#### 本节原则

- 先定义任务，再给总览，随后按依赖介绍模块。每个模块写目的、设计依据、输入与输出。
- 【铁律】模块首句用 To [具体目的], [执行者] [设计或动作]。承接引言对应问题，不能只说“提高质量”。
- 【铁律】Overview 用准确章节名与节号，每小节只引一次。写清操作与产物交接，末句指向框架图。串行、并行和反馈按实际关系写。
- 【铁律】任务定义、框架图、总览及模块使用同一套名称。输入输出一致，各阶段可见信息分清。
- 【铁律】符号先解释对象、来源、单位与下标，再使用。必要公式单独编号，并保留标点。普通操作不强造公式。
- 重点解释自己的设计，外部组件说明来源与职责。参数作用写 Method；取值、选择规则及版本写实现细节。

定义输入、输出与任务完成标准。

**English 填空模板**

Given [input objects and their sources], the task is to produce [output object] that satisfies [task requirements]. We denote [essential object] by [symbol] and define [the decision or objective]. During [training or inference], [system] has access to [available information]. [Evaluation-only information, if any] is used only for [evaluation role].


**高亮与旁批**

1. **Given [input objects and their sources]**：先给输入。填实际输入及来源。后续输出必须由这些输入得到。
2. **[output object] that satisfies [task requirements]**：输出与任务要求。填输出形式与判断标准。供后续模块和指标使用。
3. **We denote [essential object] by [symbol] and define [the decision or objective].**：必要符号。先解释对象，再定义符号。模块公式放对应小节。
4. **During [training or inference], [system] has access to [available information]. [Evaluation-only information, if any] is used only for [evaluation role].**：各阶段可见信息。分清训练、推理与评价的信息。评价答案不能充当模型输入。不存在的阶段删去。

2. **in [exact subsection A title] (Section [A]), we [design action] using [input] to obtain [intermediate output]**：一句概括一个小节。填节名、节号、执行者与操作。写清接收什么、产出什么。
3. **we [next action] using this [intermediate output] and [additional input]. This step produces [output of module B].**：交接实际产物。串行模块交接实际产物。并行模块分别写输入与汇合点。
4. **transforms this [output of module B] into [final output] for [task objective]**：收束到任务目标。末个模块给最终输出。模块数量按真实结构增删。
5. **Figure [framework] summarizes these dependencies.**：图文结构一致。框架图、总览与小节同名。三处使用相同依赖关系。

##### Stage 1 · 写清输入、操作与产物

- 每个模块写清输入、操作、产物与接收者。名称与 Method 小节一致。产物注明对象，不只叫 Features 或 Results。
- 将引言的困难对应到解决它的模块。先说明设计为何必要，再补实现细节。
- 【铁律】箭头对应真实依赖，训练、推理与评价分开。评价专用的答案与判据，不连到被测模型输入。

##### Stage 2 · 按依赖排模块

- 先定唯一主阅读方向，再排模块。同层内容成组并命名，并行分支保持并行。汇合点写明收到的产物。
- 相邻模块用短连线，箭头不穿文字。反馈放在主流程旁，注明触发条件。不为排版添加虚构的串行或反馈。
- 用一个案例串起关键模块。就近展示输入片段、中间产物和输出。不用模块名替代实际材料。

##### Stage 3 · 编码角色并逐箭头核对

- 三种边框区分输入、输出与评价材料，图例解释含义。解决关键困难的模块用统一强调色。
- 材料、操作模块和评价器旁写对象名。大框对应 Overview，内部步骤对应方法小节。同名同义。
- 逐条读箭头：“谁把什么交给谁”。再查案例来源、简称、颜色与实际字号。读不通的连接先修内容。

#### 方法模块

To [solve the specific problem assigned to this module], we [key design action]. Given [actual module input], [executor] performs [necessary operation] according to [criterion or equation]. **高亮与旁批**

### 2.7 实验

说明比较怎样做，再报告发现、关键证据和分析。

<a id="refine-attribution-comic"></a>
![铁律：归因要有对照。同一输入与共享设置下，对比完整模型和去掉模块 A 的模型。](../assets/refine-attribution-comic.png)

多个因素同时变化，不能只归因于一个。主结果也不能证明每个模块各自有效。

#### 本节原则

- 依次写：概述、设置、指标、主结果、消融、补充分析。每项分析回答引言中的一个问题。RQ 可编号，也可写进标题或首句。
- 章首先承接方法或数据，概述对象与主发现。再引出分析；名单、设置与结果分开写。
- 【铁律】Metrics 用一个紧凑自然段。先写目标，再按 1)、2)、3) 定义指标。名称只加粗，不斜体。写清定义、方向、单位、分母与汇总。交代无效输出处理。
- 结果段先给发现，再给图表、对照与关键数字。最后回答引言中的问题，说明代价与例外。
- 逐模块写消融。Setting 定义变体及共享条件，Results 分析对应结果。设置、表格与分析中的变体同名。
- 【铁律】均值与不确定性来自真实观测和明确方法。说明统计或重采样单位、数量及 SD、SE 或 CI。单次运行不能声称跨运行稳定。
- 【铁律】数据版本、范围、配置与结果对应同一协议。缺失、无效、不适用分别交代。不得只保留成功输出。
- Case Study 展示输入、中间产物与输出，解释关键设计。区分实测与构造案例，个例不能替代核心验证。

#### 实验概述

承接方法，概述发现，再预告验证与分析。

**English 填空模板**

After constructing [method, dataset, or benchmark], we evaluate [target systems or behaviors] on [evaluation scope]. The results show [verified main finding that answers the Introduction question]. Specifically, we compare [method or systems] with [comparison group] to examine [primary claim]. We then analyze [component role or remaining question] through [actual ablation, diagnosis, or further test].


**高亮与旁批**

1. **After constructing [method, dataset, or benchmark]**：接回前章产物。接回已介绍的方法或数据。点明受测对象。
2. **The results show [verified main finding that answers the Introduction question].**：先概述主发现。填最重要的实验发现。与摘要和引言一致。
3. **to examine [primary claim]**：主实验回答核心主张。说明各项贡献如何检验。RQ 可编号，也可直接写入句中。
4. **through [actual ablation, diagnosis, or further test]**：预告后续分析。填实际开展的后续分析。分别交代它们回答什么问题。

<a id="annotated-experiments-datasets"></a>

#### 数据与划分

定义实验总体、样本单位与数据范围。

**English 填空模板**

**Datasets.** We evaluate on [dataset names, versions, and citations], which contain [sample unit and task-relevant coverage]. We use [training, development, and test split or official evaluation protocol]. [Parameters or model choices] are selected using [development data], while [test split] is reserved for final evaluation. [Inclusion rules and resulting sample counts] define the evaluated population. [Additional preprocessing details] are provided in Appendix [data].


**高亮与旁批**

1. **[dataset names, versions, and citations]**：标识数据版本。名称、版本与引用放在一起。不得混用同名数据的不同划分。
2. **[sample unit and task-relevant coverage]**：说明一条样本是什么。填影响评价的输入、标签或场景。详细统计放数据节或附录。
3. **[training, development, and test split or official evaluation protocol]**：交代真实划分。填实际划分与用途。纯推理可用官方测试集。没有调参则删除选参句。
4. **[Inclusion rules and resulting sample counts] define the evaluated population**：固定统计范围。填纳入规则与有效数量。分别说明排除、不适用和无效输出。

#### 比较方法

交代比较对象、选择依据与比较条件。

**English 填空模板**

**Baselines.** We compare [our method] with [baseline family A and citations], which [shared mechanism], and [baseline family B and citations], which [different relevant mechanism]. These baselines cover [comparison dimensions related to our contribution]. All methods use [matched data, model access, resources, or evaluation conditions]. [Unmatched conditions that may affect interpretation] are reported in [settings location].


**高亮与旁批**

1. **[baseline family A and citations], which [shared mechanism]**：按路线介绍比较对象。按路线归类，再简述机制。版本与引用紧跟名称。
2. **[comparison dimensions related to our contribution]**：说明选择依据。选与贡献有关的常用或强对照。覆盖相关近期工作。
3. **[matched data, model access, resources, or evaluation conditions]**：说清比较条件。只写实际控制的条件。预算上限相同不等于信息量相同。
4. **[Unmatched conditions that may affect interpretation]**：保留影响判断的差异。标明公开报告值及其来源。闭源模型、异构硬件等差异须交代。

#### 实现细节

集中交代会影响结果的执行设置。

**English 填空模板**

**Implementation Details.** We implement [method] with [backbone or dependency versions]. [Key parameters introduced in Method] are set to [actual values] using [selection procedure and data]. Evaluation uses [execution configuration, hardware, and resource budget relevant to the comparison]. We conduct [actual repeats] over [repeat unit] and report [aggregation and uncertainty definition]. [Evaluator identity, configuration, and assessment protocol, if applicable] are specified in [protocol location].


**高亮与旁批**

1. **[backbone or dependency versions]**：固定执行版本。填实际模型、软件或代码版本。让读者能定位同一实现。
2. **[actual values] using [selection procedure and data]**：补全方法参数。填参数值、搜索范围与选择依据。一次固定的参数也须说明。
3. **[execution configuration, hardware, and resource budget relevant to the comparison]**：写影响结果的条件。填相关训练、推理、检索与解码设置。涉及成本比较时给成本口径。完整配置可放附录。
4. **[actual repeats] over [repeat unit] and report [aggregation and uncertainty definition]**：定义重复与误差。写运行次数、重复单位与统计方法。单次可报告样本统计。不能据此声称跨运行稳定。样本量不是运行次数。
5. **[Evaluator identity, configuration, and assessment protocol, if applicable]**：单独交代评价器。有判分时写谁判什么、依据什么。说明判分如何核验。无评价器则删去。

**Metrics.** We assess [target properties linked to the task] on [evaluation units and scope]. 1) **[Metric 1 full name (abbreviation)]** measures [definition, unit, direction, and denominator]. 2) **[Metric 2 full name (abbreviation)]** measures [definition, unit, direction, and denominator]. 3) **[Metric 3 full name (abbreviation)]** measures [definition, unit, direction, and denominator]. We compute [per-unit quantities] and aggregate them using [macro, micro, weighted, or other actual rule]. [Invalid, missing, and not-applicable outputs] are handled according to [defined policy], with [applicable counts or coverage] reported in [location].


**高亮与旁批**

1. **We assess [target properties linked to the task] on [evaluation units and scope].**：先说明衡量什么。填指标衡量的任务或贡献。紧接评价单位与范围。
2. **1) [Metric 1 full name (abbreviation)] measures [definition, unit, direction, and denominator].**：编号与指标定义。首次给全称与缩写。名称只加粗，不斜体。指标数量按实际增删。

##### Stage 2 · 统一坐标与面板

- 可比面板统一方法顺序、坐标尺度和图例映射。坐标写明变量、单位和好坏方向。图例放空白处，不遮关键点。

#### 消融：设置与结果

每个模块先写 Setting，再写 Results。

**English 填空模板**

**Setting.** To examine [the specific role of Module A], we compare [control variant full name] with [variant containing Module A]. The two variants differ only in [Module A or its specified replacement]. Both retain [other modules] and use [matched data, backbone, training or inference settings, and evaluation protocol]. [Required retraining and downstream changes caused by this intervention] are described in [settings location].

**Results.** **[Verified finding about Module A under these conditions].** Table [ablation] compares [the two variant rows] on [the metric tied to this module's purpose]. [Metric] changes from [control value] for [control variant] to [observed value] for [tested variant], with [measured uncertainty, if available]. This result supports [the module's role within this configuration]. [Relevant exception or trade-off, if observed].


**高亮与旁批**

1. **To examine [the specific role of Module A]**：检验哪项作用。接回 Method 的设计动机。点明本组消融检验什么。
2. **[control variant full name] with [variant containing Module A]**：定义对照变体。写清变体删除或替换了什么。设置、表格与结果须同名。
3. **Both retain [other modules] and use [matched data, backbone, training or inference settings, and evaluation protocol].**：固定其余条件。固定其他条件，说明连带变化。存在额外差异时逐项列出。此时改掉 differ only，收窄归因。训练模块按协议重新训练。
4. **[Verified finding about Module A under these conditions].**：先回答实验问题。先写发现，再给数字。如实写提升、下降或无明确差异。
5. **[the two variant rows] on [the metric tied to this module's purpose]**：分析对应对照。只分析刚定义的对照与指标。不能归入完整方法的总增益。
6. **[the module's role within this configuration]**：解释作用范围。其他模块固定时，写条件增益。不能当作独立作用或协同效应。

<a id="annotated-experiments-further-analysis"></a>

#### 补充分析

按贡献选择分析，每组回答一个明确问题。

**English 填空模板**

To investigate [question not answered by the main comparison], we [analysis action stated as a verb phrase] using [actual evidence and comparison conditions]. Figure [analysis] shows [verified pattern], with [key value or contrast] under [tested scope]. This finding explains [the aspect of the original research question supported by the analysis]. [Implication for the method or a remaining question].


**高亮与旁批**

1. **[question not answered by the main comparison]**：先说为什么还要分析。填分析目的。可检验范围、失败、成本或稳定性。
2. **[actual evidence and comparison conditions]**：写清改变与保留什么。填改变因素与固定条件。诊断比例说明对象、分母与范围。
3. **[verified pattern], with [key value or contrast] under [tested scope]**：围绕一个图给发现。先概括关系，再给关键数字。不逐点复述图形。
4. **[the aspect of the original research question supported by the analysis]**：连接全文问题。说明发现如何支持或限制主张。相关模式不等于因果机制。

<a id="annotated-experiments-case-study"></a>

#### 案例分析

沿输入、中间产物与输出，说明方法如何起作用。

**English 填空模板**

We select [case] because it contains [challenge tied to the Introduction]. Figure [case study] presents [input and available evidence]. In [method stage], [actual operation] produces [recorded intermediate artifact], where [marked evidence] determines [the next decision]. The final output [observed behavior], whereas [a comparable baseline, if available] [observed contrast]. This case illustrates [the specific operation or failure], consistent with [the relevant quantitative finding, if established].


**高亮与旁批**

1. **[challenge tied to the Introduction]**：先交代选例理由。选典型困难、关键设计或失败案例。不要只选最好的成功例子。
2. **[input and available evidence]**：从真实输入开始。给理解案例必需的输入。敏感数据须已获公开许可。
3. **[recorded intermediate artifact], where [marked evidence] determines [the next decision]**：解释关键步骤。展示可核查的中间产物。用高亮、编号和旁注解释下一步。
4. **[observed behavior], whereas [a comparable baseline, if available] [observed contrast]**：输出与差异。公平对照可并排展示。没有对照则删 whereas 分句。不得编造输出。
5. **[the specific operation or failure]**：本例说明什么。解释本例，不替代主要验证。颜色按语义分组。再用形状或标记辅助区分。

<a id="discussion"></a>
<a id="chapter-discussion"></a>
### 2.8 讨论

解释实验发现的含义与适用范围。

#### 本节原则

- 按发现、解释依据、实际意义组织。是否单列 Discussion，依论文与会议要求。
- 【铁律】区分推断与已验证机制。未经控制的因素不能写成唯一原因。保留实验适用范围。

<a id="annotated-discussion"></a>

#### 讨论：发现的含义

解释发现的含义及实际用途。

**English 填空模板**

Together, [finding 1] and [finding 2] suggest [answer to the research question] under [tested conditions]. This pattern is consistent with [explanation linked to the design], as supported by [specific comparison or analysis]. For [target use], these findings imply [practical meaning within the tested scope]. [Unresolved question] motivates further study of [specific follow-up].


**高亮与旁批**

1. **[finding 1] and [finding 2]**：已有发现。填实验章已建立的发现。各项共同回答同一个问题。
2. **[answer to the research question] under [tested conditions]**：研究含义。回答 Intro 的问题。保留发现成立的条件。
3. **[explanation linked to the design], as supported by [specific comparison or analysis]**：解释与依据。填设计解释及其支持证据。未经机制检验时保留推断措辞。
4. **For [target use], these findings imply [practical meaning within the tested scope].**：实际意义。填使用者、任务与可支持的判断。按研究类型选用。
5. **[Unresolved question] motivates further study of [specific follow-up].**：后续问题。由未回答的问题引出下一步。仅在需要时保留。

<a id="conclusion"></a>
<a id="chapter-conclusion"></a>
### 2.9 结论

回答引言的问题，概括已验证的贡献与发现。

#### 本节原则

- 用工作、设计与发现回答 Intro 的问题。压缩背景与操作细节。
- 【铁律】贡献、名称、数字及结论方向与正文一致。不新增结果或能力。
- 必要时由已述局限引出未来方向，不强加展望。

<a id="annotated-conclusion"></a>

#### 结论：工作、证据与回答

用核心设计与发现回答 Intro 的问题。

**English 填空模板**

We introduced [work name and type] to address [research problem]. By [core design and action], [work name] [actual capability]. Experiments on [evaluation scope] show [main quantitative result] and reveal [key finding]. These findings indicate [answer to the research question within the established scope].


**高亮与旁批**

1. **We introduced [work name and type] to address [research problem].**：收束贡献。填本文工作及其解决的问题。沿用 Intro 的研究对象。
2. **By [core design and action], [work name] [actual capability].**：概括设计。By 后填动作的 -ing 形式。再写核心设计能完成什么。
3. **Experiments on [evaluation scope] show [main quantitative result] and reveal [key finding].**：概括证据。填比较范围、数字与关键发现。对应摘要、引言及实验。
4. **These findings indicate [answer to the research question within the established scope].**：回答起点。写研究现在能回答什么。结论强度与正文一致。

<a id="limitations"></a>
<a id="chapter-limitations"></a>
### 2.10 局限性

本套约定用一个自然段写两个研究边界。分别以 First、Second 引出。

#### 本节原则

- 本节写本文边界；摘要与引言的 limitations 写已有研究缺口。
- 【铁律】本套 CS skill 采用一段两点，用 First / Second 起句。每点先写有据工作，再说明仍待研究的边界。官方格式与当前作者要求优先。
- 【铁律】已有工作须有据，两点各有具体对象。未测试不能写成失败。让步句不能掩盖影响结论的限制。

<a id="annotated-limitations"></a>

#### 局限：本文的研究边界

用一段两点写清本文的研究边界。

**English 填空模板**

First, although we have [completed work addressing the main difficulty], [specific boundary 1] still warrants further study. Second, although we have [another completed and verified contribution], [specific boundary 2] still warrants further study.


**高亮与旁批**

1. **First, although we have [completed work addressing the main difficulty]**：第一点：已完成什么。have 后填过去分词短语。先写已有工作，再引出边界。
2. **[specific boundary 1] still warrants further study.**：第一点：边界是什么。填未覆盖的具体条件或问题。不能只说泛化有限。
3. **Second, although we have [another completed and verified contribution]**：第二点：另一个方面。填另一项工作及其边界。同段承接，不重复第一点。
4. **[specific boundary 2] still warrants further study.**：第二点：还需研究什么。填另一项对象与条件。复数对象用 warrant。

<a id="references"></a>
<a id="chapter-references"></a>
### 2.11 参考文献

按官方格式生成文献表，核对每条引文的支持关系。

#### 本节原则

- 参考文献由会议模板与 .bib 生成。核对引文及书目信息，无需另写说明段。
- 【铁律】判断旁给支持它的原始来源。模型、数据和工具引用所用版本的论文或官方文档。
- 【铁律】核对题名、作者、年份、出处、DOI 或链接。同一论文的重复版本去重。
- 【铁律】来源的对象与条件须支持附近判断。引用文字和图均注明出处，核对许可。
- 【铁律】逐条核实引用，虚假或幻觉引用有拒稿风险。自动导出与核验不能替代人工检查。

<a id="template-references"></a>
#### 引文与书目格式

引文放 .tex，条目放 .bib，两处引用键一致。命令与书目样式沿用会议模板。

- 从出版方官网或 Google Scholar 导出 BibTeX，仍须逐项核对。
- 建议统一会议简称，期刊补全 pages 页码。无页码时沿用官方文章号。

模板仅供参考。替换方括号；无 DOI 等可选信息时，删除对应字段。

**正文引用（.tex）**

引用紧跟判断。本例用 citep；模板只支持 cite 时换用 cite。书目加载命令沿用官方模板。

```latex
[Claim supported by the cited work] \citep{source_key}.
```

**会议论文（inproceedings）**

booktitle 填论文集名；作者之间用 and 分隔。pages 填页码范围，用双连字符连接。

```bibtex
@inproceedings{source_key,
  title     = {[Verified title]},
  author    = {[Family name, Given name] and [Family name, Given name]},
  booktitle = {[Verified proceedings title]},
  year      = {[Publication year]},
  pages     = {[First page]--[Last page]},
  doi       = {[Verified DOI]}
}
```

**期刊论文（article）**

journal 填刊名；volume 填卷，number 填期，pages 填页码。

```bibtex
@article{journal_key,
  title   = {[Verified title]},
  author  = {[Family name, Given name] and [Family name, Given name]},
  journal = {[Verified journal title]},
  year    = {[Publication year]},
  volume  = {[Volume]},
  number  = {[Issue]},
  pages   = {[First page]--[Last page]},
  doi     = {[Verified DOI]}
}
```

**arXiv 预印本（misc）**

优先使用 arXiv 导出条目，核对所引版本。编译后检查编号；样式不显示 eprint 时，可用 note 保留。

```bibtex
@misc{preprint_key,
  title         = {[Verified title]},
  author        = {[Family name, Given name] and [Family name, Given name]},
  year          = {[Version year]},
  eprint        = {[Verified arXiv identifier]},
  archivePrefix = {arXiv},
  primaryClass  = {[Verified subject class]},
  url           = {[Verified arXiv URL]}
}
```

[BibTeX 官方文档：条目类型与字段](https://mirrors.ctan.org/biblio/bibtex/base/btxdoc.pdf) · [Google Scholar：导出引用](https://scholar.google.com/intl/en/scholar/help.html) · [arXiv 官方 BibTeX 导出示例](https://arxiv.org/bibtex/2604.09285) · [ACL 2026：幻觉引用拒稿声明](https://2026.aclweb.org/acl_statement/)

### 2.12 附录

补实现与评价细节，按正文入口组织。

#### 本节原则

- 按内容设实现细节、设置、补充分析等小节。节首先指向对应的正文方法或主张。正文给出附录入口。
- 【铁律】核心设计、关键证据及重要限制留在正文。附录补足复现与扩展信息。
- 【铁律】正文与附录的版本、符号、分母及结论范围一致。补充结果改变主结论时，同步修改正文。

<a id="annotated-appendix"></a>

#### 附录：说明补充内容

每节对应一项正文内容，补足复现或分析细节。

**English 填空模板**

To reproduce [method or experiment] in Section [X], this section provides [necessary implementation or evaluation details]. We specify [actual settings and selection procedure] for [all relevant systems or conditions]. Table [Y] reports [supplementary results and their aggregation], extending the analysis of [main-text question] to [additional tested condition]. The results show [supported conclusion about that condition].


**高亮与旁批**

1. **To reproduce [method or experiment] in Section [X]**：正文入口。点名对应的正文方法或实验。正文也引用本附录节。
2. **[necessary implementation or evaluation details]**：本节材料。填算法、参数、提示词或评分规则。按主题保留复现所需信息。
3. **[actual settings and selection procedure] for [all relevant systems or conditions]**：设置与选择依据。填实际设置及选择依据。覆盖本节全部比较对象。
4. **Table [Y] reports [supplementary results and their aggregation], extending the analysis of [main-text question] to [additional tested condition].**：补充结果。有补充实验时保留。写清表中内容、汇总方式与问题。
5. **The results show [supported conclusion about that condition].**：本节结论。填该条件下的发现。纯实现节删去本句及前一句。

<details><summary>连续色标与基准</summary>

**连续色标：让明暗顺序对应数值**：类别用离散色板，连续量用明暗有序的色标。偏离有意义的基准时，用发散色标。连续量不默认用 rainbow／jet。其明暗不均可能掩盖差异或制造边界。保留已有颜色含义，并检查灰度下的数值顺序。

<details><summary>气泡面积编码</summary>

**【铁律】气泡面积与数量成正比**：气泡表示非负数量时，面积须与数量成正比。半径取数量的平方根，并给大小图例与单位。数量增至 4 倍，面积增至 4 倍、半径增至 2 倍。关系来自 A = πr²；其他颜色与位置编码另解释。

#### 气泡编码：数量对应面积

1. **观察 1：**本图对照三种数量的编码，不含数据坐标轴。横向位置只作排列，v表示模拟数量。

2. **观察 2：**圆面积为πr²。左侧r=6v，右侧r=18√v。两侧最大半径均为54像素，便于比较比例。

3. **观察 3：**圆大小表示数量时，面积须成比例。人不易精确估计面积，重要比较仍须标数值或位置。

<details><summary>误差线重叠与判断</summary>

**误差线重叠：先认类型与比较设计**：不能只凭误差线是否重叠判断显著性。先看 SD、SE 或 CI 类型、样本量及独立／配对设计。用对应检验，或直接估计差值与区间。保留误差类型、重复单位和区间定义，不凭图补 p 值。

2. **观察 2：**样本SD以n−1为分母，均为√10。SE=SD/√5=√2。左侧为均值±1SD，右侧为均值±1SE。

3. **观察 3：**两种误差线回答不同问题，本图未算p值。重叠不是通用显著性判据。正式比较须按独立或配对设计选择检验或差值区间。

## 相关参考和推荐阅读

- [Weissgerber 等（2015）· 小样本连续数据为何需要展示原始观测](https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.1002128)：原始点揭示均值与误差条隐藏的分布、离群点及配对。适用于小样本连续数据，不设统一样本阈值。不禁止所有柱图。
- [Wilke（2019）· 散点重叠的处理](https://clauswilke.com/dataviz/overlapping-points.html)：先调点大小与透明度。密集散点可用二维分箱或 hexbin，解释计数或密度。保留真实坐标，不用 jitter；分箱不保留逐点位置。
- [Wilke（2019）· 颜色使用的常见误区](https://clauswilke.com/dataviz/color-pitfalls.html)：连续量用明暗有序的色标，避免 rainbow/jet 误导。类别用离散色，偏离基准时用发散色。不指定唯一色板。
- [Rougier 等（2014）· 科研绘图的十条建议](https://doi.org/10.1371/journal.pcbi.1003833)：按读者与主要信息选图，核对布局、颜色和说明。气泡表示非负数量时，面积须成比例，不能直接缩放半径。示意形状不套用定量比例。
- [Cumming 等（2007）· 误差条与组间差异的解读](https://pmc.ncbi.nlm.nih.gov/articles/PMC2064100/)：区间比较取决于误差类型、独立样本数及独立／配对设计。特定条件的重叠近似规则不能推广为通用判据。配对比较使用差值及其不确定性。

- [Henderson & Chambers (2022) · Ten simple rules for writing a Registered Report](https://doi.org/10.1371/journal.pcbi.1010571)：研究问题、适用的假设与预先规划。不要求每篇都写 RQ1/H1。
