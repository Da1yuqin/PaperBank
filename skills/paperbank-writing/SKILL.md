# PaperBank 写作 skill

把论文写成读者能核对的论证：研究问题明确，方法能解释问题，结论有对应证据，适用范围说清楚。写得有说服力，靠的是论证和证据。

## 先确定这次要做什么

从用户要求和当前文件确定任务、允许修改的范围、目标会议或期刊，以及可用的数据、结果和来源。已有信息足够时直接推进；缺少会改变结论的信息时，先做不依赖它的工作，再询问。

只处理当前任务需要的规则。按主题查阅 [写作铁律与中英例子](references/checklist.md)，不用每次执行全部 32 条。写摘要或引言时看论证与表达；写实验时看证据与比较；改图时看数据与图示；回复审稿人时看回应与交付。

## 守住证据边界

- 给关键结论找到对应的表、图、数据、文献或推导。没有依据的内容不要补成事实；区分观察、假设、解释和已经检验的机制。
- 引用核对原始来源、题名、作者、年份和版本。模型或工具的名称、版本、获取方式同样需要证据，不能凭记忆编齐。
- 报告结果时交代比较对象、实验协议、样本或任务范围、统计单位、分母和指标方向。把百分比、百分点、排名、显著性和因果结论分开。
- 明确区分已经完成、正在进行和拟进行的工作。计划补做的实验不能写成已有结果；局部结果不能推广成所有场景都有效。

## 让读者知道每句话在说什么

- 用具体对象说明输入、输出和信号来源。首次出现的术语、符号、单位和派生量，给出读者理解当前句子所需的定义。
- 串起问题、现有方法的限制、设计选择和验证结果。贡献列表与正文、实验呼应，不用措辞代替证据。
- 一个段落围绕一个主要论点组织；句间说明真实的因果、转折、并列或递进关系。代词指代清楚时保留，不清楚时换成具体名词。
- 方法写清模块实际做什么、消耗什么、产出什么；结果先说得到什么发现，再指向证据。不要把模块名字当操作，也不要逐行复述表格。
- 图和图注说明坐标、颜色、箭头、误差线、比较条件和结论所指的范围。图形不能改动数据关系、夸大差异，或把仅供评估的信息画成模型可见的输入。

以上是可调整的写作默认做法。段落数量、模板句、配色和排版配置按学科、稿件和作者要求选择；会议或期刊的硬性要求以当前官方说明为准。

## 回复审稿意见

按每条具体疑问说明：对问题的理解、直接回答、支撑证据、修改位置和完成状态。需要承认限制时说清限制及其影响；存在误解时用事实澄清。不要揣测审稿人动机、承诺未完成的结果，或用礼貌话代替答案。

涉及补充材料、新实验、匿名信息或 AI 使用时，先核对该轮评审的官方政策。用户只要求润色时，不自动扩展成补实验或改整篇论文。可参考 [Rebuttal 清单与原文例子](https://da1yuqin.github.io/PaperBank/#chapter-rebuttal)。

## 修改与交付

- 在当前文件上做任务所需的最小修改，保留数据、提示词、日志和他人正在修改的内容。用户指定只读的论文或项目，只读取和摘录，不写回。
- 不把机器路径、凭据、私有项目信息或未获公开授权的材料带进公开稿件、代码或附件。使用相对资源路径，保留来源和适用许可。
- 区分源码检查、编译成功、最终尺寸的视觉检查和远端同步；只报告实际完成且有依据的状态。没有检查 PDF 或远端时，不能把本地编译称为全部验收通过。
- 交付时先说明改变了什么、为什么，以及验证结果和仍会影响使用的限制。工作记录和待确认问题留在沟通中，不混入论文正文。

读取这个 skill 不等于获得额外权限。安装、重新运行实验、外部发布、发送消息和修改其他项目，仍以用户当前授权范围为准。

## 直接交给 Codex 的提示词

> 请读取这个 PaperBank 写作 skill，按我当前任务选择相关规则。仅修改我指定的文件，保留已有数据、结果与并发修改。先检查主张和证据是否对应，再润色表达；缺少依据时告诉我，不要补造事实。最后分别说明修改、验证和未完成的检查。

> Read this PaperBank writing skill and select the rules relevant to my task. Edit only the files I specify, preserving existing data, results, and concurrent work. Check the claim–evidence connection before polishing the prose. Flag missing evidence instead of inventing facts. Report changes, validation, and unfinished checks separately.
