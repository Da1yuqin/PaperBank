# PaperBank 写作 skill

先形成初稿，再由作者审核逻辑并精修。全文说明研究问题、关键设计与验证依据，明确核心贡献及其价值。语言专业、简洁、直白，不添加调侃、比喻或空泛修饰。

## 任务与范围

先看目标会议与作者要求。本包面向实证型 CS / AI 论文；Nature 系列用独立的 nature-writing、nature-polishing、nature-figure，不套本包的章节和贡献模板。其他领域按指定体系写。

读取当前稿件、真实结果和参考原文，确认允许修改的文件。只读任务不写回；保留原始数据、实验设置、提示词和他人修改。只查当前任务需要的规则，详细模板见 [checklist.md](references/checklist.md)。

## 起草

1. 下载当年的官方模板，先编译。
2. 有 Overleaf Git 权限就拉到本地；没有就下载源文件 ZIP。
3. 写一句话贡献，列章节、目的和页数，形成初稿。
4. 先定引言图、方法图和结果图，让合作者看懂贡献与方法，再精修正文。
5. 每节先译成中文，由作者审逻辑；确认所有章节标题后，再整理英文。

## 全文要求

- 围绕核心贡献写：已有做法在哪种条件下不足，改了什么，为什么这样改，实验支持什么。标题、摘要、引言、方法和实验使用同一组关键词。
- 一句一个主要判断，一段一个任务。后句接前句的问题或产物，连接词符合真实关系。
- 术语、缩写、符号首次出现就解释。Abstract、Introduction、Experiments 分别能读懂。
- 同一对象用同一名称。符号写对象、来源、单位和下标，不用的定义删掉。
- 正文不用 it／they 及其同族对象代词，换成简短对象名；we／our 和 this case 等带明确名词的结构可保留。原始提示词、模型回复和直接引用保持原文。
- 使用有依据的 de-identified、additional help、expert-confirmed、tailored prompt 等词突出贡献。等量替换，避免重复修饰，不为普通修饰词另建解释表。
- 发现可取短名，优先四个英文词以内，紧接具体释义；名字不能增加未验证的能力。
- 相近小节篇幅相称。超页先删重复文献配文和常规实现，次要细节移附录；保留支撑贡献的实验分析。不改模板字号、栏宽和间距。

## 章节顺序

- **Abstract**：问题、缺口、方法、结果与范围。
- **Introduction**：背景、已有方法、局限、对应设计、主要发现、贡献。贡献用原生 itemize，每项一个主要动作，长度接近，项数按真实贡献调整。
- **Introduction 进阶**：发现突出时，可用“现象→质疑→诊断→方法→验证”；领域有多个困难时，逐点展开局限，再逐点给方案。背景提供理解困难所需的信息，设计解释为何针对困难。
- **Related Work**：主标题后进主题 subsection。每组写路线、机制、扩展、缺口和本文方案；结尾用 However、To address / To solve，对齐 Intro 的对象和关键词。不同主题处理不同缺口，按类别概括文献，仅引用直接相关的工作。
- **Method Overview**：先解释设计为何有效，再说明做法。首句写核心设计如何针对 Intro 的困难，后面写目的、输入、操作、输出。用 in [Section] (ref) 定位，每个章节名和引用出现一次；后句接前句产物，保留并行关系，末句引用 framework。主语用 we、模型或模块。
- **Method 小节**：围绕创新点组织。先写目的和设计为何处理该困难，再写必要计算与产物；不要把本节写成 Preliminary。常规实现简写，复现细节仍给全。公式编号，符号就近解释。训练、推理、评价分开，说明信号来源和更新对象。
- **Experiments**：说明 Intro 主张的验证依据。Setup 定义指标与设置，基线按路线分组；分析解释发现、可能原因与对应贡献，不逐行重复数值。一段优先讲一个实验、图表与结论。消融固定其他条件，检验对应设计；保留失败尝试，分析影响判断的负结果。RQ 按研究需要使用。
- **Discussion / Limitations**：解释发现，写具体局限及影响。
- **Conclusion**：回到开头的问题，不添新结果。
- **References / Appendix**：引用回查原文；实现与补充实验放附录，正文给入口。

模板按实际内容增删。段数、配色和句式是写作默认，会议硬性要求看当年官方说明。

## 证据

每项主张对应图、表、数据、文献或推导。引用回查作者、题名、年份、版本和支持范围；模型名与实际版本一致。缺材料就指出缺口，不编结果或引用。

比较写清对象、协议、样本、分母和指标方向。分清记录与独立样本、百分比与百分点。观察、解释和机制分开；有限测试不推广所有场景，计划不能写成结果。

## 图

先写图要回答的问题，再定布局。统计图用 Python 读真实数据；概念、框架、案例图可用 imagegen。每条箭头对应真实依赖，评价信息不能画成推理输入。

按最终栏宽起稿，统一字体；图内字号为正文字号至小 2 pt。白底、低饱和、同类同色，再配形状、线型或纹理。通栏约 16:9、单栏约 4:3，按内容调整。

统计图优先矢量 PDF；生成图可叠原生文字，但位图封装不等于全矢量。图注写比较、发现、单位和图例，解释分母与误差。尽量三行，必要定义保留。放回论文检查字号、裁切、引用顺序和可读性。

## Rebuttal 与 revise loop

读取完整 review：Summary 核对理解，Strengths 记录已认可的贡献，Weaknesses 与 Questions 提取关切。逐问引用原意见，首句直接回答，随后给证据、解释与位置。流程用真实案例展示。感谢简短，不猜对方动机。请求不适用时解释条件；合理批评应修改，存在分歧时检验争议前提并给依据。

初稿完成后，按原 review 检查：原问题 → 回复位置 → 剩余缺口 → 最小改法 → 所需证据。已有实验能够回答时直接使用，不盲目重跑全部基线。先查遗漏、证据与逻辑，再压缩文字、调整语气。修改后重查同一问题清单；问题覆盖完整、证据对应、逻辑通顺且篇幅合规后停止。缺实验交给作者决定，模拟不预测评分变化或录用。

第二轮只答新增问题。AC 总结写关键问题、回应、证据和限制，不请求提分或接收。补实验、链接、修订稿和 AI 使用按当轮政策。

## 交付

保留数据、记录和并发修改。公开材料不用机器路径、凭据或私有内容，资源用相对路径，出处和许可保留。

检查实际改动、编译页数和最终 PDF；远端同步单独确认。工作记录留在沟通里，不混入论文。安装、跑实验、发布和修改其他项目仍需相应授权。
